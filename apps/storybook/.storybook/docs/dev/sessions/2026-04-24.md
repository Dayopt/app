- Radix Popover と Input の autoFocus を組み合わせる時は `onOpenAutoFocus={(e) => e.preventDefault()}` で競合回避（Popover 即時クローズの典型原因）

learned:

- dnd-kit は自作 collision detection / 仮想化統合を組み合わせると保守不能になる。最初から公式 Multiple Containers サンプルを playground で動かしてから本番に移植するほうが結果的に速い（chunks 方式で solo / group を `__root__` SortableContext、子タグを nested SortableContext で管理）
- Radix Popover の `onOpenAutoFocus` と Input の `autoFocus` は競合する。focus が一瞬 outside 扱いになり Popover が即時クローズする
- next-intl の APP_NAMESPACES は route group ごとに必要 namespace を明示する。session timeout 警告のような (app) layout で mount される shared component が touch する namespace（auth など）を漏らすと runtime で MISSING_MESSAGE
- Supabase 型再生成で関数 signature が non-null array に変わった場合、null 渡しを維持するなら `as never` で variance を逃す（RPC 実装側が null を許容するなら DB 挙動は変わらない）
- 同じ「タグ編集」操作でも、複数の呼び出し起点があるなら inline popover より global modal が圧倒的に簡素（呼び出し側で open state を持たない設計が選択肢として優先される）
- 設計書の path 移動を伴う archive 作業は、相対 path（src/ ref / sibling project ref）の depth 修正が必ず付随する。git mv 後に内部リンクを目で全件確認する
