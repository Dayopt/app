# Secrets Management

Dayopt の全シークレットは 1Password で一元管理する。`.env.local` に実値は書かない。

## 原則

1. **実値をディスクに残さない** — `.env.local` に書くのは `op://` 参照だけ
2. **コピペしない** — 「これは公開OK」の判断自体を運用から排除する
3. **Vault 分離で環境混在を防ぐ** — Production キーは触る時だけ unlock する

---

## 保管対象

「API キー」「SSH 鍵」で分類すると漏れる。**漏れた時に何が起きるか** で分類する。

### ① API キー / アクセストークン

プログラム的アクセス権の鍵。Supabase service_role, Stripe secret, Anthropic, Sentry auth token, Vercel token, GitHub PAT…

漏洩 = そのサービスの権限範囲で全操作可能。最優先。

### ② SSH 鍵 / 署名鍵

- **SSH 秘密鍵**: GitHub push 権限そのもの。漏れると任意コミットを自分名義で押し込める
- **commit 署名鍵** (SSH signing / GPG): 「検証済みコミット」偽装

**1Password SSH Agent に移行** すると `~/.ssh/` から秘密鍵ファイルを消せる。Touch ID 越しでしか使えなくなる。Mac 盗難耐性が上がる。

```txt
# ~/.ssh/config
Host *
  IdentityAgent "~/Library/Group Containers/2BUA8C4S2C.com.1password/t/agent.sock"
```

### ③ DB 接続情報 / 接続文字列

Supabase DB 直接 URL、pooler URL、将来の Redis 等。

API キーと別扱いの理由: 文字列内に user・pass・host・port が一体化してるので、Slack に「繋がらない、URL これなんだけど」と貼る事故が起きやすい。個別フィールドに分解して持つ。

### ④ OAuth / サービスアカウント

- Google OAuth client secret (将来 GCal 連携時)
- Apple Developer `.p8` / 証明書 / `.mobileprovision`
- service account JSON

**ファイル形式は Document 機能で丸ごと保管**。テキストフィールドに貼らない。

### ⑤ リカバリー系 (最重要・見落とし注意)

再発行できないもの。ここが一番ダメージでかい。

- **各サービスの 2FA リカバリーコード**: Stripe / Supabase / Vercel / GitHub / Apple / Google / Anthropic Console。電話紛失時の唯一の復旧手段
- **ドメインレジストラの recovery 情報**: dayopt.app 乗っ取られたら事業終わる
- **TOTP seed**: 1Password で生成すれば端末 1 つで完結 (※下記の注意点参照)
- **Stripe 本人確認書類スキャン**: 再提出が面倒

> **TOTP を 1Password に入れることの注意点**
>
> 厳密には「パスワードと TOTP が同じ金庫に入る」ので 2FA の独立性は下がる。ただ master password + Secret Key + Touch ID + デバイス所持の組み合わせは実質的に独立 Authenticator 相当以上の強度とされる。「面倒で 2FA を切る」事故を防げる方が現実的メリットが大きい。違和感あるなら TOTP だけ別アプリ維持でも OK。

## Vault 構成

### `Dayopt-Staging` (普段 signin)

| Item          | Field                                                                                                                        | 用途                                                                                                     |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `supabase`    | `url`, `anon-key`, `service-role-key`, `send-email-hook-secret`, `cron-secret`, `db-password`, `access-token`, `project-ref` | Staging Supabase 一式 (Edge Functions 含む)                                                              |
| `upstash`     | `rest-url`, `rest-token`                                                                                                     | Redis (rate limit / cache)                                                                               |
| `recaptcha`   | `secret-v3`, `secret-v2`, `site-key-v3`, `site-key-v2`                                                                       | v3 / v2 両方運用                                                                                         |
| `stripe-test` | `secret-key`, `webhook-signing-secret`, `pro-price-id`, `publishable-key`                                                    | Stripe test mode                                                                                         |
| `resend`      | `webhook-secret`                                                                                                             | webhook endpoint は環境ごと別登録                                                                        |
| `sentry`      | `dsn`, `org-slug`, `project-slug`                                                                                            | Sentry staging project                                                                                   |
| `slack`       | `billing-webhook-url`                                                                                                        | 課金通知 (環境ごとに別 channel 推奨)                                                                     |
| `app`         | `url`, `recovery-code-pepper`                                                                                                | **`recovery-code-pepper` は失うとユーザーの recovery code が全員復旧不能。別メディアに二重バックアップ** |

### `Dayopt-Production` (触る時だけ unlock)

Staging と同構造。Stripe のみ item 名が `stripe-live/` に変わる (解錠時に「本番触ってる」と即時認識できるため)。`sk_live_...` と本番 `service_role` はこの vault にしか存在しない状態を保つ。

| Item          | Field                                                                     |
| ------------- | ------------------------------------------------------------------------- |
| `supabase`    | Staging と同構造                                                          |
| `upstash`     | Staging と同構造 (必要に応じて)                                           |
| `recaptcha`   | Staging と同構造                                                          |
| `stripe-live` | `secret-key`, `webhook-signing-secret`, `pro-price-id`, `publishable-key` |
| `resend`      | `webhook-secret`                                                          |
| `sentry`      | Staging と同構造                                                          |
| `slack`       | `billing-webhook-url`                                                     |
| `app`         | `url`, `recovery-code-pepper`                                             |

### `Dayopt-Shared` (環境非依存)

| Item              | Field / 種別                                                      | 用途                                                                                                                                 |
| ----------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `anthropic`       | `api-key-dev`, `api-key-prod`                                     | キーは環境別に発行して両方格納                                                                                                       |
| `resend`          | `api-key-dev`, `api-key-prod`, `from-email`                       | webhook secret は各環境 vault 側                                                                                                     |
| `github`          | Login item: `pat`, TOTP, recovery codes, `contact-repo`           | GitHub MCP (repo scope)                                                                                                              |
| `github-ssh`      | SSH Key item                                                      | `~/.ssh/` から秘密鍵ファイルを削除し 1Password Agent 経由に切替                                                                      |
| `vercel`          | `token`, `team-id`, `project-id-staging`, `project-id-production` | Vercel CLI / MCP                                                                                                                     |
| `google`          | `site-verification`                                               | Search Console verification                                                                                                          |
| `domain`          | `registrar-login` + 2FA + recovery codes                          | dayopt.app 管理 (**乗っ取られたら事業終わり、二重バックアップ必須**)                                                                 |
| `recovery-codes`  | 横断 index、各サービスごと field                                  | Stripe / Supabase / Vercel / GitHub / Apple / Google / Anthropic Console。**正は各 Login item 側、これは index**。更新時は両方同時に |
| `apple-developer` | `.p8` / 証明書 (Document 保管)                                    | PWA App Store 化する時                                                                                                               |

**Login item 共通ルール**: 各サービスの Login item には以下を必ず紐付ける。

- password
- TOTP (別 Authenticator から移行)
- recovery codes (`NOTES` または専用 field、正本はここ)

各 item の `NOTES` 欄には以下を必ず書く。半年後の自分が救われる。

```
発行日: YYYY-MM-DD
発行場所: https://dashboard.xxxxx.com/...
権限/scope: (例: Stripe restricted key - read_only on charges)
再発行手順: (3行で)
revoke手順: (1行で)
依存先: (このキーを使っている script / service)
```

## `.env.local` の書き方

実値は書かず、`op://` 参照だけ。コミット可能 (するかは別として)。

```bash
# Supabase (Staging)
NEXT_PUBLIC_SUPABASE_URL=op://Dayopt-Staging/supabase/url
NEXT_PUBLIC_SUPABASE_ANON_KEY=op://Dayopt-Staging/supabase/anon-key
SUPABASE_SERVICE_ROLE_KEY=op://Dayopt-Staging/supabase/service-role-key

# Upstash Redis
UPSTASH_REDIS_REST_URL=op://Dayopt-Staging/upstash/rest-url
UPSTASH_REDIS_REST_TOKEN=op://Dayopt-Staging/upstash/rest-token

# reCAPTCHA
RECAPTCHA_SECRET_KEY_V3=op://Dayopt-Staging/recaptcha/secret-v3
RECAPTCHA_SECRET_KEY_V2=op://Dayopt-Staging/recaptcha/secret-v2
NEXT_PUBLIC_RECAPTCHA_SITE_KEY_V3=op://Dayopt-Staging/recaptcha/site-key-v3
NEXT_PUBLIC_RECAPTCHA_SITE_KEY_V2=op://Dayopt-Staging/recaptcha/site-key-v2

# Stripe (test)
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=op://Dayopt-Staging/stripe-test/publishable-key
STRIPE_SECRET_KEY=op://Dayopt-Staging/stripe-test/secret-key
STRIPE_WEBHOOK_SECRET=op://Dayopt-Staging/stripe-test/webhook-signing-secret
NEXT_PUBLIC_STRIPE_PRO_PRICE_ID=op://Dayopt-Staging/stripe-test/pro-price-id

# Resend (api-key は Shared、webhook-secret は環境別)
RESEND_API_KEY=op://Dayopt-Shared/resend/api-key-dev
RESEND_FROM_EMAIL=op://Dayopt-Shared/resend/from-email
RESEND_WEBHOOK_SECRET=op://Dayopt-Staging/resend/webhook-secret

# Anthropic (dev key)
ANTHROPIC_API_KEY=op://Dayopt-Shared/anthropic/api-key-dev

# Sentry
NEXT_PUBLIC_SENTRY_DSN=op://Dayopt-Staging/sentry/dsn

# Slack
SLACK_BILLING_WEBHOOK_URL=op://Dayopt-Staging/slack/billing-webhook-url

# App
NEXT_PUBLIC_APP_URL=op://Dayopt-Staging/app/url
RECOVERY_CODE_PEPPER=op://Dayopt-Staging/app/recovery-code-pepper

# GitHub
GITHUB_TOKEN=op://Dayopt-Shared/github/pat
GITHUB_CONTACT_REPO=op://Dayopt-Shared/github/contact-repo

# Google
GOOGLE_SITE_VERIFICATION=op://Dayopt-Shared/google/site-verification
```

vault 名がパスに出るので「今どの環境で動いてる?」が `.env.local` を見るだけで分かる。

## 起動

`package.json` の scripts を `op run` でラップする:

```json
{
  "scripts": {
    "dev": "op run --env-file=.env.local -- next dev",
    "build": "op run --env-file=.env.local -- next build",
    "migration:create": "op run --env-file=.env.local -- supabase migration new",
    "types:generate:staging": "op run --env-file=.env.local -- supabase gen types typescript --project-id $SUPABASE_PROJECT_REF > src/lib/database.types.ts"
  }
}
```

普段は `npm run dev` で従来通り。値はメモリ経由で注入される。

### Touch ID

`op` の settings で Touch ID unlock を有効化しておく。体感遅延ほぼゼロ。

```bash
op signin --help  # 初回設定確認
```

## Claude Code / Codex CLI との連携

CLI 側でも環境変数が必要な場合は同様に `op run` でラップ:

```bash
op run --env-file=.env.local -- claude
```

`.envrc` + direnv で自動化する場合:

```bash
# .envrc
eval "$(op signin)"
dotenv_if_exists .env.local
```

## Vercel 本番 / Staging のデプロイ先

`op` はローカル開発専用。デプロイ先の環境変数は **Vercel の Env Variables UI** に入れる。

- 1Password を **master** として扱う
- Vercel には手動で同期 (年数回のコピペは許容)
- Vercel 側の値を変更した場合は 1Password 側も必ず更新

## 移行優先度 (まだやってないものがあれば上から)

1. **SSH 鍵を 1Password Agent 管理に移す** — 30 分、Mac 盗難耐性が桁違いに上がる
2. **2FA リカバリーコードを全サービス分集約** — Stripe / Supabase / Vercel / GitHub / Apple / Google / Anthropic Console
3. **TOTP を 1Password に集約** — 別 Authenticator 使ってるなら移行
4. **ドメインレジストラ recovery 情報** を `Dayopt-Shared/domain` に追記
5. **ローカルの `.env*` を全部 grep** — 生キー残ってないか確認、あれば `op://` 参照化

```bash
# 生キー残存チェック
rg -n "sk_live_|sk_test_|sbp_|sk-ant-|ghp_|whsec_" --hidden -g '!node_modules' -g '!.git'
```

## 運用ルール

### やっていいこと

- `.env.local` をコミットする (`op://` 参照のみなら問題なし)
- `op://` 参照をチャット / Slack に貼る (参照文字列は単体では無価値)
- `Dayopt-Staging` には常時 signin

### 絶対にやらないこと

- 実キーを `.env.local` に直書きする (一時的にも)
- 実キーをチャット / Slack / Issue に貼る
- Production キーをローカルの `.env.local` から参照する (Production は通常 Vercel 環境でのみ評価)
- `NEXT_PUBLIC_` だから安全、という判断ショートカット

## 詰まった時

| 症状                        | 対処                                                                         |
| --------------------------- | ---------------------------------------------------------------------------- |
| `op run` で `not signed in` | `eval "$(op signin)"`                                                        |
| 値が空で注入される          | vault 名・item 名・field 名の typo チェック。`op read "op://..."` で単体確認 |
| Touch ID が出ない           | システム設定 > 1Password > Touch ID 再有効化                                 |
| キーを rotate した          | 1Password 側を更新 → Vercel 側も更新 → 該当サービス側で old key を revoke    |

### キー単体の存在確認

```bash
op read "op://Dayopt-Staging/supabase/service-role-key" > /dev/null && echo OK || echo FAIL
```

`> /dev/null` で値を標準出力から消し、存在確認だけ残す。

### 現在の参照展開結果を確認 (実値は出さない)

```bash
# MISSING のキーだけ報告する安全版
op run --env-file=.env.local -- node -e "
  const keys = [
    'NEXT_PUBLIC_SUPABASE_URL','SUPABASE_SERVICE_ROLE_KEY',
    'UPSTASH_REDIS_REST_URL','UPSTASH_REDIS_REST_TOKEN',
    'RECAPTCHA_SECRET_KEY_V3','STRIPE_SECRET_KEY','STRIPE_WEBHOOK_SECRET',
    'RESEND_API_KEY','ANTHROPIC_API_KEY','RECOVERY_CODE_PEPPER',
    'NEXT_PUBLIC_SENTRY_DSN','SLACK_BILLING_WEBHOOK_URL',
    'NEXT_PUBLIC_APP_URL','GITHUB_TOKEN'
  ];
  for (const k of keys) console.log(k.padEnd(40), process.env[k] ? 'OK' : 'MISSING');
"
```
