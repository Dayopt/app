learned:

- knip は `next.config.mjs` 内の動的 path string (`createNextIntlPlugin('./src/lib/i18n/request.ts')`) を解析せず false positive を出す
- knip の unused exports 判定は barrel re-export と impl export を区別しない。barrel から消すと連鎖で impl 側が孤立する（再 knip で新しい unused files が生える）
- commitlint の subject-case ルールで PascalCase / 大文字始まり subject (例 `TimeColumn`) は弾かれる。日本語または lowercase で始め、id を末尾の `(C-XXX)` に置くと安定
- husky lint-staged は git stash 経由で staged file を一時退避するため、commit 失敗時に git status が空になる場合がある
- `whitelist` 方式（実 import を抽出して残すべき symbol のみ残す）は naive な regex だと JSDoc の例文を拾うため不正確。コメント / コード行を区別する filter が必須
