conventions:

- calendar / shell / modal 等の feature-agnostic な client state は lib/stores に配置し hub 宣言する（features/ からは re-export せず直接 lib/stores から import）
- server state と持続化したい client state を両方扱う store は、persist middleware ではなく server sync + hydration gate の組み合わせで実装する
- hydration gate は「store への apply 完了」を trigger とし、error / paused state では gate を開けて UI を表示する（偽装しない）
- rate limit / turnstile 等の cross-cutting security util は lib/{domain}/ に集約し、app / web 両リポで同じパターンを採る
- Sentry beforeSend の PII scrubbing は allow-list 方式ではなく全フィールド走査方式（Drop by default）
- mobile は閲覧専用モード前提で新 UI を作り、編集操作が混入しないようガードを component レベルで書く
- 空状態 / 通知系 i18n は Pre-suasion ルール（価値・可能性先出し）を英訳にも徹底する

learned:

- persist middleware を外して server sync に切り替える際、hydration gate を fetch 完了ではなく apply 完了で判定しないと「fetch は成功したが store への反映が遅れる」窓で古い値が表示される
- TanStack Query の paused state（offline 等）で gate を閉じたままにすると UI が永続ブロックする。error / paused は gate を開けて loading 表示にフォールバックする必要がある
- localePrefix='as-needed' の next-intl middleware は locale prefix 無し URL も許容するため、locale 剥がし regex を `^/(?:en|ja)?/?` 形式に堅牢化しないと一部ルートで落ちる
- Sentry の beforeSend で PII scrub を書く際、request headers / user / breadcrumbs / contexts / extra / tags を全部走査しないと漏れる（特に breadcrumbs.data に平文 email が入る）
- Codex のレビュー指摘は P0（機能バグ / セキュリティ） / P1（UX / 回帰リスク） / P2（コード品質）の 3 段階に分けると 1 日で網羅処理できる
- knip は prod deps の未使用も検出するので、lint:deadcode を週次で回せばパッケージ漸減も自動化できる
