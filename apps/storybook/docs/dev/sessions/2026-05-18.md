decisions:

conventions:

- monorepo の lint は `turbo run lint` で各 workspace に委譲。root から `--filter @dayopt/product` 経由で個別実行可能
- monorepo の pre-commit hook は cwd を `apps/product` に切替えて lint-staged を走らせる（root 一括では false positive が出る）
- 超過 overlay の visual は破線枠のみ。テキストラベルは追加しない（情報密度を下げ、視覚で読み取らせる）
- seed.sql の entries は `actual_start_time` / `actual_end_time` を必ず明示（2-layer model 後は省略時 NULL になり test が assertion を読み違える）
- merge_tags_with_hierarchy のようなマイグレーション RPC は、エラー時に `error.message` だけでなく `error.code` / `error.details` も logger に渡す

breaking:

- root の `package.json` から `dependencies` / `devDependencies` を `apps/product/package.json` と `apps/storybook/package.json` に移動。root は scripts と pnpm.overrides のみ
- `npm` 系コマンドの代わりに `pnpm` が一次手段。`npm run` は workspace を解決できないため動作しない
- 超過 overlay の i18n キー（テキストラベル文言）を削除
- inspector の構造変換中に pre-flush（debounced save）が失敗した場合、conversion 自体を中止する（旧仕様: pre-flush 失敗を握りつぶして変換だけ通していた）

learned:

- Turborepo の `turbo.json` で `pipeline.lint.dependsOn` を `^typecheck` にすると、上流 workspace の型情報が揃ってから lint が走るため eslint の TS rule が安定する
- pnpm workspace の `--filter` は scope 名 (`@dayopt/product`) と path filter (`./apps/product`) の両方を受ける。CI では path filter の方が rename に強い
- React の `useEffect` cleanup 内で `clearTimeout` の戻り値を返さずに直接呼ぶ箇所が複数残っていた。tooltip など hover-out で即時アンマウントするコンポーネントで stale timer による setState を踏む
- tRPC の `protectedProcedure` で `ctx.userId` が string | undefined 扱いになる ESLint hooks 違反は、`zod.string().nonempty()` で input 側に縛り直すと型ガード無しで解消できる
- supabase CLI のメジャー upgrade（2.95 → 2.99）で `setup-cli` の認証 argument が変わる。CI で pin している場合は明示的に追従が必要

tried_and_failed:

- 最初の monorepo 移行で root の `dependencies` を残したまま `pnpm install` を試したら、workspace 解決と root のフラットインストールが競合して lock file が壊れた。root を scripts only にして解消
- pre-commit を root 一括の lint-staged で走らせると、未 stage の `apps/product/.next` が走査対象に紛れて誤検知が出た。cwd を `apps/product` に切替える構成に変更
- CI で supabase 2.99.0 を試したら認証フローが壊れて 2.98.0 に下げた。翌週もう一度 pin 上げを試す
- EntryCard 2-layer 構造の最初の試案で planned 枠と actual 枠を独立 div として render したが、wrapper の border-radius が二重に出て破綻。actual を planned の inner overlay にして 1 枠で表現する形に統一
