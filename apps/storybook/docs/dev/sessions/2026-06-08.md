decisions:

- planned origin エントリで actual_start_time が null の場合、start_time を表示位置として採用。entry-adapter.ts の null ガード（`return null`）を削除し、planned エントリを常にカレンダーに描画する
- パスワード変更前に signInWithPassword で現在パスワードを検証。Supabase の updateUser 自体は再認証不要だが、セキュリティ上の best practice としてユーザー主導変更には現パスワード確認を挟む
- 作成プレビューの左アクセントボーダーを削除し upcoming エントリと視覚的統一。DraftEntryBlock の `border-l-2` を廃止

learned:

- entry-adapter.ts で `!actual_start_time || !actual_end_time` の場合 return null していた旧実装が、「予定だけエントリ（計画済み・未記録）」をカレンダーから完全除外する根本原因だった。planned の場合は start_time / end_time を displayStart/displayEnd として使う
- CalendarGridContent の `overflow-hidden` が予定レイヤー（絶対配置）の高さ揃えを妨げていた。overflow-visible への変更でグリッドからはみ出るリサイズハンドルも正常に動作するようになった
- `Object.prototype.hasOwnProperty.call(overrides, key)` パターンは `key in overrides` より安全。テストのモックビルダーで null を明示的に渡すケースを区別できる
