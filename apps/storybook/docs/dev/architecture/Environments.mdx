## 環境変数の管理

### 1Password master / replica

1Password を master とし、Vercel Env / GitHub Secrets / Supabase Dashboard secrets は replica として手動同期する。`vercel env pull` は通常の local dev flow ではなく、生成された `.env.local` は unsafe / temporary として削除対象にする。

### Zodバリデーション

サーバーサイド環境変数は `src/env.ts` で起動時にバリデーション。
必須変数が欠けていると、具体的なエラーメッセージで即座に検知できる。

```typescript
// サーバーサイドコード
import { env } from '@/env';

const supabase = createServerClient(
  env.NEXT_PUBLIC_SUPABASE_URL,
  env.NEXT_PUBLIC_SUPABASE_ANON_KEY,
  { ... }
);
```

> **注意**: `NEXT_PUBLIC_*` はNext.jsがビルド時に文字列置換するため、
> クライアントコード（`client.ts`等）では従来通り `process.env` を直接参照する。

### `.op-env.local`

repository root の `.op-env.local.example` を `.op-env.local` にコピーし、必要な `op://` 参照だけを使う。実値・dummy secret・placeholder secret は書かない。

## 単一 project 運用のリスク

- preview / dev が production DB を直接触るため、**破壊的操作（`db reset`、大量 delete）は厳禁**
- RLS を信頼してユーザー分離する前提
- テストユーザーと実ユーザーが同じ DB に共存する

### Vercel 環境変数

```
Production     → Production Supabase
Preview        → Production Supabase（全 Preview ブランチ共通）
Development    → Production Supabase（1Password master から手動同期）
```

## オフライン開発（フォールバック）

ネットワーク接続がない場合、ローカル Supabase を使用できる。

```bash
# ローカルDBを起動（Docker必要）
supabase start

# 環境変数でローカルDBを指定
USE_LOCAL_DB=true pnpm dev
```

> 通常の開発では Docker 不要。オフライン時のみ使用。

## マイグレーション

詳細な手順は `apps/storybook/docs/dev/guides/MigrationChecklist.mdx` を参照。

### 自動適用

`main` ブランチに `supabase/migrations/**` の変更がpushされると、
GitHub Actions（`.github/workflows/supabase-migration.yml`）が自動で Production Supabase に適用。

### 手動適用（緊急時）

```bash
supabase link --project-ref yvglwblxrnrenfifsnje
supabase db push
```

### リンク状態の確認

```bash
supabase projects list
# LINKED列に●があるプロジェクトが現在リンク中
```

## GitHub Actions Secrets

CI/CD ワークフローで使用するシークレット一覧。GitHub の Settings > Secrets and variables > Actions で管理。

| シークレット名                  | 用途                          | 使用ワークフロー       |
| ------------------------------- | ----------------------------- | ---------------------- |
| `SUPABASE_ACCESS_TOKEN`         | Supabase CLI 認証             | migration, integration |
| `PRODUCTION_DB_PASSWORD`        | Production DB パスワード      | migration              |
| `NEXT_PUBLIC_SUPABASE_URL`      | Supabase URL（ビルド時）      | ci, e2e                |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase 匿名キー（ビルド時） | ci, e2e                |
| `NEXT_PUBLIC_APP_URL`           | アプリ URL（ビルド時）        | ci, e2e                |

### GitHub Environments

| 環境名        | 用途                        | 保護ルール     |
| ------------- | --------------------------- | -------------- |
| `development` | E2E / Integration テスト    | なし           |
| `production`  | Production マイグレーション | 手動承認が必要 |

> **production environment の設定**: GitHub > Settings > Environments > production > Required reviewers を有効化し、自分を追加する。これにより `migrate-production` ジョブが自動実行されず、承認を待つ。

## デプロイフロー

```
feature branch → push → Vercel Preview URL 自動生成
                  ↓
              PR → main マージ
                  ├── Vercel: 自動 Production デプロイ
                  └── GitHub Actions: Production Supabase にマイグレーション自動適用

バージョン記録（任意）:
  git tag v0.X.0 → GitHub Actions → GitHub Release 作成
  ※ タグはデプロイトリガーではない
```

## 実機テスト手順

1. ブランチをプッシュ

   ```bash
   git push origin feature/xxx
   ```

2. Vercel が自動で Preview デプロイ

3. Preview URL にモバイルでアクセス
   - 固定URL: `app-git-{branch}-dayopt.vercel.app`

4. Preview でテスト（本番と同じ DB）

## トラブルシューティング

| 症状                           | 対処                                                          |
| ------------------------------ | ------------------------------------------------------------- |
| マイグレーションが反映されない | Production にリンクしてから `supabase db push` を実行         |
| Preview デプロイがエラー       | Vercel ダッシュボードでビルドログを確認                       |
| Production が paused           | Supabase ダッシュボード → Settings → General → Resume         |
| 環境変数エラーで起動しない     | `.op-env.local` の `op://` 参照と 1Password signin 状態を確認 |
