# Data Flow

Calendar Review panel のデータ取得・変換・表示のパイプライン。

---

## 全体像

```
PostgreSQL RPC 関数
  → tRPC ルーター (entry/stats feature)
    → TanStack Query (並列取得・自動キャッシュ)
      → 純粋計算関数
        → Calendar panel UI
```

Review の補助 insight はルールベースで client-side 評価:

```
TanStack Query (Layer 1/2 と同じ pageData)
  → useDiscoveries (純粋関数で発見リストを評価)
    → compact panel UI
```

---

## tRPC エンドポイント

### Layer 1: KPI メトリクス

**ルーター**: `src/features/entry/server/statistics.ts`

| エンドポイント          | Input                  | 説明                      |
| ----------------------- | ---------------------- | ------------------------- |
| `getCumulativeTime`     | dateRange              | 期間内の記録時間合計      |
| `getStreak`             | —                      | 連続アクティビティ日数    |
| `getPlanRate`           | dateRange              | 計画率                    |
| `getEstimationAccuracy` | dateRange              | タグ別見積もり精度        |
| `getEnergyMap`          | dateRange              | 時間帯×曜日エネルギー分布 |
| `getContextSwitches`    | dateRange              | タスク切替回数            |
| `getBlankRate`          | dateRange + wake/sleep | 空白時間率                |

### Layer 2: チャート

**ルーター**: `src/features/entry/server/statistics.ts`

| エンドポイント             | Input         | 説明                   |
| -------------------------- | ------------- | ---------------------- |
| `getDailyHours`            | `{ year }`    | ヒートマップ用日次集計 |
| `getMonthlyTrend`          | `{ months? }` | 月次推移               |
| `getDayOfWeekDistribution` | dateRange?    | 曜日別分布             |
| `getHourlyDistribution`    | dateRange?    | 時間帯分布             |

### 補助 insight（ルールベース）

サーバー endpoint なし。Layer 1/2 と同じ `getStatsPageData` の結果を `useDiscoveries` で評価する。

---

## 状態管理

### useReviewFilterStore (Zustand)

| State         | 型       | 説明                 |
| ------------- | -------- | -------------------- |
| `granularity` | `'week'` | 表示粒度             |
| `currentDate` | `Date`   | ナビゲーション基準日 |

### URL 状態

Calendar URL の `panel=review` と `reviewTagId` で表現する。期間は Calendar の `date` search param を使う。

---

## キャッシュ戦略

- Layer 1/2: TanStack Query の staleTime でキャッシュ。週・日付の組み合わせがキャッシュキー
- Insights タブ: 同じ pageData を共有し、`useDiscoveries` で再計算（メモ化）
