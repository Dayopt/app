# 意思決定の原則（前提としてのスタンス）

策定日: 2026-08-17（[#2098](https://github.com/Dayopt/dayopt/issues/2098) → [#2099](https://github.com/Dayopt/dayopt/issues/2099)）

## 位置づけ

日常判断は `CLAUDE.md` §シンプルルール（判断層）5 箇条がメインのまま変わらない。本ファイルはその下に敷く前提としてのスタンスで、次の 3 つの場面だけで参照する: **シンプルルールで裁けない判断**、**そもそもの前提を考え直す場面**、**ルール自体の改訂**。日常のたびに本ファイルへ降りるのではなく、迷った瞬間に戻るのはあくまでシンプルルール 5 箇条。

Claude は提案・レビュー時にこのルール順で評価し、抵触があれば明示的に指摘する。

## 適用範囲

プロダクト・技術・組織について「作る / 変える / やめる」を決める場面。特に不可逆性・コスト・不確実性を伴う判断。

## ルール（衝突したら番号が小さい方が勝つ）

1. **破滅に賭けるな。**
   問い: 失敗しても、会社・信頼・安全は残るか?
   残らないなら期待値がどれだけ高くてもやらない。戻せる形にするか、影響範囲を閉じてから。

2. **思惟に反するなら、速くてもやらない。**
   問い: これは誰の、どんな変化のためか即答できるか?

3. **迷ったら、学びが最大の方を選べ。撤退条件を決めてから始めよ。**
   問い: 何を検証し、どう測り、いつ止めるか言えるか?
   言えない行動は延期。撤退条件が来たら感情に関係なく止める。

4. **同点なら、扉が多く残る方を選べ。**
   問い: この決定は後続の選択肢を増やすか、減らすか?

5. **非対称なら、賭けろ。**
   問い: 損失に天井があり、利得に天井がないか?
   Yes なら Rule 1 に反しない限りためらわずコミット。

## 日常用ショートカット

「これは安く学べる賭けか?」で即答できるものはそのまま進む。即答できない案件だけ Rule 1→5 を順に通す。

## AI（Claude）の運用

- 提案・レビュー時、このルール順で評価し、抵触があれば明示的に指摘する。
- 撤退条件のない実験提案には、Rule 3 の問いを返す。

## メタルール

- このルール自体も Rule 3 の対象。四半期ごと、または大きな失敗の直後に見直す。
- ルールは増やさない。新しい教訓は既存の「問い」の改善として吸収する。

## 検証実績

原則 1（破滅）× 原則 5（非対称）の優先関係は、実例「paid billing 有効化」で検証済み: 誤課金による信頼毀損は「天井のある損失」ではなく原則 1 の判定対象として扱い、破滅面を先に閉じてから（storage backup [#1971](https://github.com/Dayopt/dayopt/issues/1971) をゲート条件にした現行運用と同型）原則 5 で賭ける。番号順の優先 + 「Rule 1 に反しない限り」の文言がこの実判断を再現できることを確認した（[#2099](https://github.com/Dayopt/dayopt/issues/2099) コメント参照）。

見直しサイクルは新しい儀式を作らず、月次ガーデニング（`.claude/skills/gardening/SKILL.md`）へ畳み込む。
