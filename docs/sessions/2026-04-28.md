conventions:

- `prettier --write` の auto-import 削除に対しては「import + 使用箇所」を 1 edit で投入する。Read で stale を回避できないため、別の場所への利用追加 → import 追加の順で進めると安全
- pure logic を分離する時は同じ component ディレクトリ内に sibling として配置（feature の lib/ には feature 横断的に必要な物だけ昇格）
- 楽観更新で 2 種類の cache（list / hierarchy）を持つ場合、`onMutate` で両方を Promise.all で cancel → 両方 setData → context に previousList/previousHierarchy を返し、onError で両方 rollback する
- DnD の collision detection で「self を drop 不可」を強制する際は moveTagTree 内部の null return より collision 段階で除外する方が UX が安定する（ユーザーが「線が出ない」を見て drop を諦められる）
- Tailwind v4 の arbitrary values（`transition-[padding-bottom]` / `pb-[calc(...)]` 等）は lint rule `tailwindcss/no-arbitrary-value` で reject される。`transition-all` で代替するか、必要なら CSS variable + custom utility を `lib/styles/utilities.css` に @utility で定義
- ScrollableCalendarLayout のような **内部スクロール container** を持つページで、document scroll に依存した UI 制御（auto-hide bar / sticky header の隠し）を入れると、内部スクロールが capture phase で fire してしまうため副作用が出る。document scroll かどうかを判定する手段がない場合は内部スクロール page では機能を無効化する
- 「pb の動的切替」は scroll position の clamp と組み合わさると **scroll-down → pb shrink → scrollTop clamp → 上 scroll と誤検知 → pb expand → 下 scroll の無限ループ** に陥る。動的 padding は scroll-listening UI と本質的に相性が悪いので避ける
- 時刻入力 component (TimeInput / ClockTimePicker) のように **draft state と committed state が分離している** UI では、preset 選択や上流 value 更新時に draft が古いまま blur で再 commit される race が生じやすい。draft の dependency には preset value も含めて useEffect で sync する
- vaul の DrawerHandle は default margin 0。`mt-2` 程度の上余白を持たせて grabber が drawer 上端にぴったり貼り付かないようにする。Dayopt の標準は `mt-2`（shadcn/ui 公式の `mt-4` よりコンパクト）

learned:

- ROOT container の bbox が children の合計と一致するため、最後のアイテムより下に「ROOT 専用」zone は存在しない。pointerWithin で over=ROOT にするには items 列の外に明示的 droppable を置くしかない
- @dnd-kit の `useSortable` は active item にも transform を当てて cursor 追従させる。EntryCard 風の「source は原位置に残す」見せ方を実現するには `style.transform` に `isDragging ? undefined : CSS.Translate.toString(transform)` を渡す
- `noopSortingStrategy: SortingStrategy = () => null` で他 item の reflow を停止すると drag UX が落ち着くが、splice 後の `findRootIndex` fallback で「source 上 release」が末尾再挿入を引き起こす silent reorder バグが顕在化する。moveTagTree 先頭で `if (activeId === overId) return null` のガードが必須
- `prettier --write` (lint-staged) の sort-import で「使用されていない import」を削除する pass が走るため、import を追加する edit と使用箇所追加の edit が分かれると後者の edit までに前者が消える。1 edit 内に同居させるか、使用箇所先行で追加する
- `scrollbar-gutter: stable` (`scrollbar-stable` utility) は drag 中の動的 height 変化が引き起こす scrollbar 現出 → content 幅縮小によるレイアウトずれを防ぐ。Sidebar / Stats のような可変高さスクローラーには予防的に付ける価値がある
- vaul の `[data-vaul-handle]` は `display: block; margin-left: auto; margin-right: auto; height: 5px; width: 32px` だけで、上下 margin を一切持たない。shadcn/ui 公式の vaul wrapper は `mt-4 mx-auto rounded-full bg-muted` を直接 div で描画している
- `useHideOnScroll` の `document.addEventListener('scroll', ..., { capture: true })` は document scroll だけでなく内部スクロール（任意の `overflow-y-auto` 要素）の scroll event も捕える。ScrollableCalendarLayout の内部スクロールでも auto-hide が誤発火するのはこのため
- 動的 padding-bottom + scroll-listening UI の相性： scrollHeight が縮むと browser が scrollTop を `min(scrollTop, scrollHeight - viewportHeight)` で clamp する。これが「上方向のスクロール」として scroll listener に観測されるため、auto-hide / auto-show の状態が反転して無限ループになる
- TimeInput の draft race： preset を tap した瞬間に commit + form value が更新される。だがその直後 blur が発火すると、blur handler が draft（preset 反映前）を再度 commit してしまう。`useEffect` で draft を value と sync するか、blur 時に「直前 commit があったか」を guard する必要がある
- min_event_height を変更する際、entry の resize slider は `aria-valuemin` を hardcode していると常時最小値が古いままになる。const から参照するか、計算式に min_event_height を組み込む
