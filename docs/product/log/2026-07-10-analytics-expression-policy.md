# ADR-026: アナリティクスの表現は「見積もり係数・差分・週次の1つの補正」の3点に絞る

time-model-split（[ADR-025](./2026-07-09-time-model-split.md)）完了後のアナリティクスで何を表現するかの決定。1つの統計サービス（タグ別の予実ペア）を3つの瞬間に配る構造とし、Toggl 的レポートは作らない。

## 背景・当時の前提

- ADR-025 の分割により、タグ別の予実データ（plan と `plan_id` で紐づく logs）が初めて正しく計算できるようになる。`auto_migrated` provenance により移行実体化分を分母から除外できる
- [principles.md](../principles.md) の「ズレの3点分散」で作成時フィードフォワードが「3点の中で最重要・未実装」と位置づけ済み。週次補正の提示場所は未決だった
- [strategy.md](../../business/strategy.md) の制約: 成績表化しない（§4-6）、比較は過去の自分だけ、分析を「行き先」にしない（§4-10）

## 決定と理由

アナリティクスで表現するのは以下の3点のみ。すべて同一の統計サービス（タグ別の予実ペア集計）を燃料とする。

| #   | 表現するもの                | 定義                                                                                                                                                                           | 表示場所                                                                                                |
| --- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| 1   | タグ別見積もり係数          | plan 単位で Σ(logs duration) ÷ plan duration の比を1つ作り、直近4週の**中央値**。**plan 側タグで束ねる**。`auto_migrated` / skipped の plan は除外。**n≥3 未満は何も出さない** | 作成時フィードフォワード。比ではなく draft に掛けた実時間で提示（「このタグの直近実績は45分前後です」） |
| 2   | 今日/今週の差分             | Step 7 の4分類（未記録 / やらなかった / 予定に対する記録± / 予定外）そのまま。±0 非表示                                                                                        | 右パネル差分側                                                                                          |
| 3   | 精度の推移・週次の1つの補正 | \|中央値の比 − 1.0\| が最大 かつ n≥3 のタグを1つ選び補正案を提示。推移は改善時のみ言及（悪化時は沈黙）                                                                         | 右パネルの振り返り側                                                                                    |

理由:

- 中央値: 平均は1回の外れ値（大事故の日）に引きずられ、「静かに教える」研究者トーンと相性が悪い
- n≥3 の沈黙閾値: 根拠の薄い数字を出さない。初期ユーザーの画面をノイズで埋めない
- **タグ帰属は plan 側**: フィードフォワードは plan を作る瞬間に draft のタグで引くため、計上キーと参照キーが一致する plan 側タグが一貫する。Step 7 の「Review 表示は log 側タグ優先」とは**用途が異なる別の決定**であり、矛盾ではない
- 実時間提示: 比率（1.5x）は計器っぽいが認知負荷が高い。「45分前後」は次の入力を直接助ける

## 却下した選択肢と、なぜ捨てたか

- **「予定外時間の割合」の表示** — 「今週の記録の35%は予定外」は計画の立て方への気づきになるが、成績表化の一歩手前。v1 では出さず、差分リストに予定外 log が事実として並ぶだけで十分とする。将来、週次補正の条件分岐（予定外が支配的な週は補正文言を変える）として再検討の余地は残す
- **タグ帰属を log 側に統一** — Review 方針（log 側優先）と揃うが、作成時に引くキーとのねじれが出る。用途別に分ける方が実装も説明も単純
- **平均値** — 外れ値耐性がない
- **合計時間・円グラフ・期間フィルタ等のレポート** — Toggl / RescueTime の領土（strategy §4-10）。分析を行き先にしない

## 影響・やること

- 全体順序の決定: **作成時フィードフォワード → Phase 2（外部カレンダー取り込み）→ ローンチ準備 → 出荷**。外部カレンダーをローンチに先行させる理由: Google Calendar 取り込みが無いと創業者含めターゲットの日常に入れず、v1 ループ（7日間自走）の検証ができない。例外として公開中 LP の誤表記修正（lp-launch-content 必須修正 A〜E）だけはローンチ準備を待たず先に実施する
- [principles.md](../principles.md) の未決「週次補正の提示場所」を解消（右パネル振り返り側）
- 実装の前提は time-model-split Step 2-9 の完了（logs が正になってから統計は意味を持つ）
- 委任ブリーフ: 作成時フィードフォワード / 週次の1つの補正 / LP 必須修正 / Phase 2 設計書起こし を GitHub Issue として起票する
