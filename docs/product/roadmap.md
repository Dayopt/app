# Roadmap - リリースまでの道のり

プロダクトリリースに向けて必要なことを逆算で整理。

**現状**: MVP開発中
**目標**: 品質優先、時期は柔軟に調整

---

## Now / Next / Later

日付ではなく優先度で整理。柔軟性を保ちながら方向性を示す。

### Now（今取り組んでいること）

> 自分で毎日使える状態にする

| テーマ   | 内容                         |
| -------- | ---------------------------- |
| コア機能 | ログ記録・振り返り機能の実装 |
| 認証     | ユーザー登録・ログイン       |
| インフラ | 本番環境構築・デプロイ       |

### Next（Nowの次にやること）

> 他の人が使って問題ない状態にする

| テーマ       | 内容                                 |
| ------------ | ------------------------------------ |
| UX改善       | オンボーディング・エラーハンドリング |
| ベータテスト | 5-10人でテスト・フィードバック収集   |
| 法務         | 利用規約・プライバシーポリシー       |

### Later（いずれやること）

> 一般公開・課金開始

| テーマ         | 内容                   |
| -------------- | ---------------------- |
| 決済           | Stripe連携・料金プラン |
| マーケティング | LP・SNS・ローンチ準備  |
| 成長           | 分析・改善サイクル     |

---

## 詳細チェックリスト

### 1. プロダクト（コア機能）

**Done**: ユーザーが日々のログを記録・振り返りできる状態

- [ ] **ログ記録機能**
  - [ ] 時間ブロックの作成・編集・削除
  - [ ] カテゴリ/タグ付け
  - [ ] メモ・コメント追加
- [ ] **振り返り機能**
  - [ ] 日次ビュー
  - [ ] 週次サマリー
  - [ ] 簡易グラフ表示
- [ ] **基本的なバグフィックス**
  - [ ] クラッシュするバグがない
  - [ ] データが消えるバグがない
- [ ] **パフォーマンス**
  - [ ] 初回ロード3秒以内
  - [ ] 操作時のラグがない
- [ ] **モバイル対応**
  - [ ] スマホで操作可能
  - [ ] タッチ操作が快適

### 2. ユーザー体験

**Done**: 初めてのユーザーが迷わず使い始められる

- [ ] **オンボーディング**
  - [ ] 初回起動時のチュートリアル（3ステップ以内）
  - [ ] サンプルデータの表示 or 空状態の案内
- [ ] **エラーハンドリング**
  - [ ] エラー時に何が起きたか分かるメッセージ
  - [ ] リトライ方法の案内
- [ ] **フィードバック表示**
  - [ ] 保存完了の通知
  - [ ] ローディングインジケーター
- [ ] **空状態（Empty State）**
  - [ ] 「最初のログを記録しよう」的な案内
- [ ] **ヘルプ**
  - [ ] 基本的な使い方ページ（5項目程度）
  - [ ] 問い合わせ先の明記

### 3. アカウント・認証

**Done**: ユーザーが安心してアカウントを作成・管理できる

- [ ] **登録フロー**
  - [ ] メールアドレス + パスワード登録
  - [ ] メール認証（任意だが推奨）
  - [ ] ソーシャルログイン（Google等）は後でもOK
- [ ] **ログイン・ログアウト**
  - [ ] セッション管理
  - [ ] 「ログイン状態を保持」オプション
- [ ] **パスワードリセット**
  - [ ] メールでリセットリンク送信
  - [ ] 有効期限設定（24時間等）
- [ ] **アカウント削除**
  - [ ] ユーザー自身で削除可能
  - [ ] 削除前の確認ダイアログ
  - [ ] 関連データの完全削除
- [ ] **データエクスポート**
  - [ ] JSON or CSV形式でダウンロード
  - [ ] 全データ一括エクスポート

### 4. インフラ・運用

**Done**: 安定して動作し、問題発生時に気づける状態

- [ ] **本番環境**
  - [ ] Vercel / Cloudflare等にデプロイ
  - [ ] 環境変数の設定
  - [ ] 本番用DBの準備
- [ ] **ドメイン**
  - [ ] ドメイン取得（dayopt.app）✅ 取得済み
  - [ ] DNS設定
  - [ ] SSL証明書（自動発行）
- [ ] **バックアップ**
  - [ ] DB自動バックアップ（日次）
  - [ ] バックアップからの復旧手順確認
- [ ] **監視**
  - [ ] エラー監視（Sentry等）導入
  - [ ] エラー通知設定（Slack/メール）
  - [ ] 死活監視（任意）
- [ ] **アクセス解析**
  - [ ] 簡易アナリティクス導入（Plausible等）
  - [ ] DAU/MAU程度が見れればOK

### 5. 法務・ビジネス

**Done**: 法的に問題なくサービス提供できる状態

- [ ] **利用規約**
  - [ ] サービス内容の説明
  - [ ] 禁止事項
  - [ ] 免責事項
  - [ ] 規約変更時の通知方法
- [ ] **プライバシーポリシー**
  - [ ] 収集する個人情報の明記
  - [ ] 利用目的
  - [ ] 第三者提供の有無
  - [ ] Cookie使用の説明
- [ ] **特定商取引法に基づく表記**
  - [ ] 販売業者名
  - [ ] 連絡先
  - [ ] 販売価格
  - [ ] 支払方法・時期
  - [ ] 返品・キャンセルポリシー
- [ ] **決済システム**
  - [ ] Stripe連携
  - [ ] サブスクリプション設定
  - [ ] 請求書・領収書発行
  - [ ] 解約フロー
- [ ] **料金プラン**
  - [ ] プラン設計（無料/有料の境界）
  - [ ] 価格設定
  - [ ] 料金ページ作成

### 6. マーケティング

**Done**: サービスの価値が伝わり、登録できる状態

- [ ] **ランディングページ**
  - [ ] ヒーローセクション（一言で価値を伝える）
  - [ ] 機能紹介（3つ程度）
  - [ ] 料金表
  - [ ] CTAボタン（登録/始める）
  - [ ] フッター（利用規約等へのリンク）
- [ ] **メッセージング**
  - [ ] キャッチコピー確定
  - [ ] プロダクトの一言説明（30秒で説明できる）
  - [ ] ターゲットユーザーの明確化
- [ ] **ビジュアル素材**
  - [ ] スクリーンショット（3-5枚）
  - [ ] デモ動画 or GIF（30秒程度）
  - [ ] OGP画像
- [ ] **SNS**
  - [ ] Xアカウント作成
  - [ ] プロフィール設定
  - [ ] 固定ツイート準備

### 7. ローンチ準備

**Done**: リリース日に告知して、ユーザーを迎える準備完了

- [ ] **ベータテスト**
  - [ ] テスター5-10人確保
  - [ ] フィードバックフォーム用意
  - [ ] 致命的な問題の洗い出し
- [ ] **フィードバック収集**
  - [ ] アプリ内フィードバックボタン
  - [ ] 問い合わせフォーム or メール
- [ ] **ローンチ告知**
  - [ ] 告知ツイート下書き
  - [ ] リリースノート（CHANGELOG）
- [ ] **初期ユーザー獲得**
  - [ ] 知人への声かけリスト
  - [ ] 関連コミュニティへの投稿計画
  - [ ] Product Hunt等への投稿（任意）

## フェーズ分け

### Phase 1: MVP完成

**ゴール**: 自分で毎日使える状態

- 1.プロダクト完了
- 3.アカウント・認証完了
- 4.インフラ（最低限）

### Phase 2: クローズドβ

**ゴール**: 5-10人が使って致命的問題なし

- 2.ユーザー体験完了
- 7.ベータテスト実施
- フィードバック反映

### Phase 3: リリース

**ゴール**: 一般公開して課金開始

- 5.法務・ビジネス完了
- 6.マーケティング完了
- 7.ローンチ準備完了

---

## 優先度の考え方

**必須（リリースブロッカー）**

- コア機能が動く
- 致命的なバグがない
- 利用規約・プライバシーポリシー
- 決済システム・料金プラン

**重要（できれば欲しい）**

- オンボーディング
- エラー監視
- ランディングページ

**後回しOK**

- 高度な分析
- プレスキット
