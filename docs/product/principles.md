# プロダクト原則(体験設計)

[`strategy.md`](../strategy.md) の原則を画面と操作に翻訳する設計文書。プロダクト原則そのもの(§4)は strategy.md を正とする。ここでは v1 完成の定義と、それを実現する体験設計を扱う。

- strategy.md(不変)と違い、この文書は**設計が進むたび更新される**
- strategy.md と矛盾する設計はここに書かない。衝突したら strategy.md が優先
- 未決事項は本書末尾の「設計上の未決リスト」で扱う

本書は**目標状態**を含む。実装済みかどうかは各節の状態表示を正とし、現在の外部挙動を確認する場合は`product/specs/`を参照する。

## v1「完成」の定義

機能が揃ったら完成ではない。**このループが最小摩擦で 7 日間自走したら v1 完成:**

1. 朝(または前夜): ルーティンのゴースト確定 + 数ブロックの計画が **2分以内**（**未実装**。「ルーティン」の繰り返しブロック・ゴースト確定という概念自体が実コードに無い。単発のブロック配置は実装済みで、アクティビティを押して時間に置く 3 ステップ以内で完了する — 「計画する」節参照）
2. 日中: ブロック開始の合図が来る。記録はワンタップ、押し忘れは後から訂正できる（**半分実装**。ワンタップ記録と事後訂正は実装済み — `RecordPlanButton`([TimeblockRecordActions.tsx](../../apps/product/src/features/timeblock/components/editor/TimeblockRecordActions.tsx)) が過去 Plan を同時間帯の Record へワンタップで記録し、過去 Plan のタイトル・タグ・メモ訂正は `temporal-constraints.md` で許可済み。**ブロック開始・終了の合図（opt-in 通知）は未実装** — push notification / Notification API の配線が product 側に無い）
3. 夜: カレンダーを開いた瞬間、今日の予定と実績のズレが見える(操作ゼロ)（**実装済み**。下記「ズレの3点分散」① の 2 レーンカレンダーがそのまま実装）
4. 週末: ルールベース統計が「来週の 1 つの補正」を提示する（**再実装中**。旧 `WeeklyReflectionPanel` はレポート面の 4 章構成への一新（[#2575](https://github.com/Dayopt/dayopt/issues/2575)）で撤去した。後継は 2 章の「見積もりの鏡」で、過去予定 30 分以上・箱 3 つ以上のアクティビティから癖の強い順に最大 3 件を出す）
5. この間、アプリの都合の通知・煽りがゼロ（**該当なし判定**。②の合図通知自体が未実装のため、通知・煽りは構造的にゼロ。②が実装された時点で改めて判定が要る）

残作業リストは「このループの欠けと摩擦」だけで構成する。あったら良い機能はリストに入れない。

## 全体構成: カレンダーが主役

- コンテンツ領域は常にカレンダー(Day/Week のタイムライン)。各日カラムを **Plan レーン(アウトライン・淡色)と Record レーン(塗り・主役)の2レーン**(ADR-025（削除済み、git 履歴参照）)で並べ、これが操作ゼロのレビュー面を兼ねる
- 分析の置き場は `/report` フルページ(Sidebar のタブから遷移)。ただしレポートビルダーにはしない — 期間指定の複雑なフィルタ・カスタムレポート・保存フィルタの入れ子は足さない([strategy.md §4-10](../strategy.md))
- この構成の理由: 予定と実績を同じタイムラインで対にする設計の視覚的ペイオフは2レーンの並びであり、それはカレンダーの上でしか見せられない。LP のスクリーンショット 1 枚で差別化が伝わる絵もこれ

## ズレの3点分散

レビュー機能を1つの部屋にせず、3つの瞬間に分散する。

| #   | 場所                       | 役割                                                                                                               | 状態                                                                                                                                                                                                                                                                              |
| --- | -------------------------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | カレンダー上の2レーン      | Plan レーンと Record レーンの並びで予定と実績のズレが**操作ゼロ**で見える。今日のズレの一次表示                    | 実装済み                                                                                                                                                                                                                                                                          |
| 2   | `/report` フルページ       | 今日/今週の差分、アクティビティ別の傾向、セグメント別の比較。「この作業は予定と記録が1時間ずれている」が分かる場所 | 実装済み                                                                                                                                                                                                                                                                          |
| 3   | 作成時のフィードフォワード | ブロックを置く瞬間に「30分の予定ですが、このアクティビティの直近実績は45分です」と統計が静かに教える               | 実装済み（`EstimationFeedforward`、[EstimationFeedforward.tsx](../../apps/product/src/features/timeblock/components/editor/EstimationFeedforward.tsx) + [statistics-feedforward-service.ts](../../apps/product/src/features/timeblock/server/statistics-feedforward-service.ts)） |

学習が一番転移するのは振り返っている時ではなく、**次の計画を立てている時**。③は過去を責める表示ではなく未来の入力を助ける表示であり、「守れる計画」(strategy.md §2)に最も直結する。

## `/report`(現状と設計方針)

### 現状

Sidebar のタブから遷移するフルページ。1 スクロール構成でセクションを縦に並べる（タブ分割はしない）。

1. **差分** — 予定と実績の diff を事実として見せる。GitHub の diff 表示を参考に作った
2. **予実の傾向(Time P/L)** — アクティビティ別の予実比較
3. **セグメント** — 選択したアクティビティの組み合わせの単体の数字 + 直前期間比較

### 評価

差分セクションは just idea 起点だが、**筋が良いので残す**。理由:

- ターゲット(AI を使いこなす知的労働者、中核は開発者)にとって diff は母語。「予定と実績の diff」はズレ＝計器(strategy.md §2)の最も自然な表現
- 「差分 = 今日の事実」「傾向・セグメント = 期間・アクティビティの解釈」という役割分担は、証拠ベースの進捗感(strategy.md §4-6)と整合する

**タブ分割 vs 1スクロールの論点は決着した**（2026-08-19）。「開いた瞬間にズレが見える」はタブの初期表示側にしか効かず、フルページでは縦に並べれば両方が開いた瞬間に見える。3 軸(アクティビティ/カテゴリー/セグメント)を持ち込んでもタブ構造では軸の数だけタブが増えるが、1 スクロールなら増える時に「画面が長くなる」という目に見えるコストが必ず伴う（レポートビルダー化への歯止めがレイアウトそのもので効く）。

### 設計方針(固定)

- **セクションは 3 つで固定。** 増やすには一覧そのものを書き換える必要がある(条件分岐で生やさない)
- **1画面で終わる読み物以上にしない。** カスタムレポート・期間指定の複雑なフィルタは足さない(Toggl/RescueTime の領土)。`range` は `day` | `week` の 2 値のみで、任意期間・月次は持たない
- **セグメントは合計・比率を出さない。** 円グラフ・積み上げ・「合計 100%」は使わない。単体の数字 + 過去の自分との比較のみ
- **成績表化しない。** 点数・ランク・評価ラベルは出さない。事実(時間の伸び、頻度)の提示のみ(strategy.md §4-6)

## 計画する

- アクティビティを押して時間に置く。3 ステップ以内で完了
- ルーティン(繰り返し設定したブロック)は当日にゴーストとして現れ、ワンタップで確定。確定されなかったルーティンもズレデータになる

## 実行する

- ブロック開始・終了の opt-in 通知が合図をくれる(フローに入った人間は時間感覚を失うので、これがないと計画は朝作った飾りになる)
- 記録はワンタップ。押し忘れは後から自由に訂正できる

## つながる(MCP / API)

- MCP / API で全データを読み書きできる。ユーザーのチャット画面で「今これやってるからアクティビティで2時間つけておいて」が動く
- API の書き込みはデフォルトでゴースト経由([strategy.md §4-3](../strategy.md))。直接確定の許可は要検討(下記未決リスト)
- 週次にルールベース統計で「来週の 1 つの補正」を提示する(AI 不要)。提示場所は `/report` の予実の傾向セクション、表現する数値の定義は ADR-026（削除済み、git 履歴参照）

## 設計上の未決リスト

- 2レーンの視覚表現の磨き込み(Week「予定+記録」の密度対応、差分数字の添え方)
- 作成時フィードフォワードの表示形式(どこに・どのくらい静かに出すか。表現する数値は ADR-026（削除済み、git 履歴参照） で確定済み)
- ゴーストの視覚表現と有効期限の挙動
- ゴースト経由 API 書き込みの詳細(直接確定を許す `confirmed` フラグの是非、外部カレンダー同期の繰り返しイベントの扱い)
