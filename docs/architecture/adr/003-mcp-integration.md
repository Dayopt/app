# ADR-003: MCP統合

> accepted（2026-02-26・遡及記録）

---

## コンテキスト

Claude Codeを開発ワークフローに統合する中で、外部ツール（DB、Storybook、ドキュメント）との接続が手動で非効率だった：

- Supabaseのスキーマ確認やデータ操作のたびにダッシュボードを開く必要があった
- ライブラリドキュメントの参照が都度Web検索に依存し、バージョン不一致のリスクがあった
- StorybookのコンポーネントプレビューとAI開発フローが分断されていた

MCP（Model Context Protocol）の登場により、これらの外部ツールをClaude Codeから直接利用できる統合レイヤーが実現可能になった。

---

## 決定

MCPを外部ツール統合レイヤーとして採用し、3サーバー構成で開発ワークフローに組み込む。

---

## 詳細

### サーバー構成

`.mcp.json` に3つのMCPサーバーを定義：

| サーバー         | タイプ | 用途                                     |
| ---------------- | ------ | ---------------------------------------- |
| `supabase-local` | HTTP   | ローカルSupabaseへの直接アクセス         |
| `context7`       | stdio  | ライブラリドキュメントのリアルタイム参照 |
| `storybook-mcp`  | HTTP   | Storybookプレビューとの連携              |

### 権限管理

`.claude/settings.json` でMCPツールの許可・拒否を管理。機密性の高い操作（データ削除等）はデフォルトで確認を要求する設計。

### Feature境界との関係

MCPはADR-002で定義したfeature境界の「外側」に位置する。MCPサーバーはfeatureの内部構造を知らず、公開APIやDBスキーマを通じてのみアクセスする。これにより、feature境界の原則を壊さずに外部ツール統合を実現している。

---

## 結果

### メリット

- DB操作、ドキュメント参照、UIプレビューがClaude Code内で完結し、コンテキストスイッチが減少
- ライブラリドキュメントが常に最新バージョンを参照でき、古い情報によるバグを防止
- 開発者がMCPサーバーを追加するだけで新しい外部ツールを統合可能

### トレードオフ

- ローカル開発環境でSupabaseとStorybookが起動している必要がある（HTTP接続のため）
- MCPプロトコル自体がまだ発展途上であり、破壊的変更のリスクがある
- サーバー障害時のフォールバック（手動操作への切り替え）が暗黙的
