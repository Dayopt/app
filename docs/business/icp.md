# Part A: ペルソナ(実践編)

## A1. ペルソナの核心

**「正しいやり方は分かってるのに、道具がない」人。**

- 時間管理に困ってる初心者ではない。すでにいろいろ試して、自分なりの方法論を持ってる
- Toggl を触ったことがある、タイムボクシングを知ってる、生産性について考えたことがある
- タスク管理や情報整理はすでに AI や既存ツール（GitHub Issues / Notion / Slack）に任せていて、**自分の時間の全体感を見る場所がない**
- Claude / ChatGPT のチャットで複数の MCP を横断して「他にやった方がいい活動ある？」と聞くのが自然な人。だから Dayopt の役割は会話の中の AI ではなく、その会話を可能にする**構造化された時間データの正典**（[strategy.md §3](../strategy.md)）
- 開発者はその中核だが、開発者に限らない。創業者自身がアーキタイプユーザー
- 最初にお金を払うのは「もう何かしらやってる人」

## A2. ジムの比喩

プロダクトの価値は普遍的(運動が体にいいのと同じ)。ただし最初の顧客は「すでに走ってる人」。

ニッチを攻めるのは市場を狭くするためではなく、**最初の熱量を作るため**。

## A3. 行動パターン

### ツール遍歴

| ステップ | 行動                 | 結果                                                   |
| -------- | -------------------- | ------------------------------------------------------ |
| 1        | カレンダーで予定管理 | 「実績」が残らない                                     |
| 2        | Toggl等で時間記録    | 記録が面倒で続かない、または記録だけで改善に繋がらない |
| 3        | TODOアプリで管理     | 完了/未完了だけで「何時間使ったか」が見えない          |
| 4        | 複数ツール併用       | 行き来が面倒、データが分断、サイクルが回せない         |

### AI との働き方

- タスクの分解・調査・下書きは AI に委譲し、自分は判断と実行に集中する働き方が既に定着している
- ツールへの審美眼があり、操作数・速度・画面の少なさに敏感。「一手多い」だけで乗り換える
- 横断的な考察（「先週の時間の使い方どうだった？」）はチャットでやるのが自然。アプリ内 AI チャットはむしろノイズ

### 心理的プロファイル

- **自分↔自分** の関係で完結する(他者への共有欲求が薄い)
- 進捗は他人との比較ではなく、過去の自分との比較で確かめたい
- 「進める」「決する」「高める」の3本能が強い(裏付けは [Part B](#part-b-本能マッピング理論編))

## A4. 創業者の原体験 — Problemの起点

ペルソナの問題は、創業者自身の問題でもある。「痛み」ではなく「合理的な不満」が起点。

### 3つの不満

1. **既存ツールがそれぞれ中途半端** — Togglは記録だけで面倒。TODOは管理方法がバラバラ。カレンダーは予定だけ
2. **本来一緒であるべきものが分かれてる** — 予定と記録は同じ「時間の使い方」なのに別のツールで管理。振り返りもブラッシュアップもしづらい
3. **上位に確信がある** — タイムボクシングが最良の方法だと知っている。リソース配分を可視化したい。なのに最適化されたツールがない

### LP向けリフレーミング

LPでは「道具の断片化」(下位ジョブ)ではなく、**「サイクルが回せない」(上位ジョブ)**から入る。

- 計画はカレンダーにある。記録はTogglにある。分析は…どこにもない
- 3つのツールを行き来しても、このサイクルは回らない
- だから明日を今日より良くする手がかりが得られない

## A5. Before → After

|            | 状態                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------ |
| **Before** | 計画は立てるのに守れない。1日が終わって、見積もりのどこがズレたのか説明できない。                |
| **After**  | ズレが毎日の学習になる。見積もりを直す → 計画が守れるようになる → 「守れる計画」が立つ日が続く。 |

# Part B: 本能マッピング(理論編)

「Dayoptを使う人はどんな人で、何を求めているのか」を、進化心理学に基づく動機理論で整理する。

## B1. 結論

Dayoptは「内向きの充実」を求める人のためのツール。ターゲットが AI・ツールの上級者になっても、この軸は変わらない — 変わるのは「なぜそれを求めるか」の解像度（挫折からの回復ではなく、**方法論への確信と道具の不在**）。

**刺激する本能(6つ):**

- 高める・進める(メイン)→「見積もり精度が上がった」「前に進んだ」
- 決する・物語る(サブ)→「自分で選んだ」「意味がある」
- 安らぐ・有する(補助)→「安心」「蓄積」

**刺激しない本能(2つ):**

- 属する・伝える → コミュニティなし、シェアなし

**向く人:** 自分の時間を自分で経営したい人。進捗を他人の承認ではなく自分の証拠で確かめたい人
**向かない人:** AI に全部決めてほしい人、みんなでやりたい人、ご褒美が欲しい人

### なぜこの整理が必要か

1. **機能開発の判断基準** → この本能に刺さるか?
2. **マーケティングメッセージ** → どの本能に訴えかけるか
3. **向かない人の明確化** → 無駄な獲得コストを避ける
4. **競合との差別化** → 「内向きの充実」特化

## B2. 理論的背景と出典

進化心理学に基づく動機理論をマーケティングに応用したフレームワークを使用している。

### 学術原典

**Forbes, David L. (2011). "Toward a Unified Model of Human Motivation"**
Review of General Psychology, Vol. 15, No. 2, 85-98.
DOI: 10.1037/a0023483

Forbesは過去1世紀の動機理論を「化学の周期表」のように体系的に統合。106の動機概念を3×3マトリックス(9領域)に整理した。

### マーケティング応用

**鈴木祐『進化論マーケティング』**

Forbesの9領域を、日本語の動詞で覚えやすい「8つの本能」に再構成。実践的なマーケティングフレームワークとして提示。

### 理論的限界と最新研究

- Forbes (2011) には生物学的動機と認知的動機の区別がない、精神的領域(正義・道徳・超越)が欠如、などの指摘がある
- Pincus (2022-2024) が 9セル → 12セルに拡張し「Spiritual」領域を追加（2023 "The structure of human motivation", BMC Psychology）
- 精神的領域はDayoptの文脈に関係しないため、Forbes (2011) + 鈴木祐の8本能フレームワークで十分と判断

## B3. Forbes 3×3マトリックスと8つの本能

### Forbesの構造

**行:Where?(変化はどこで起こるか)**

| 英語          | 日本語 | 意味       |
| ------------- | ------ | ---------- |
| Intrapsychic  | 内心的 | 自己の内部 |
| Instrumental  | 道具的 | 物質世界   |
| Interpersonal | 対人的 | 社会世界   |

**列:What type?(どんな種類の変化か)**

| 英語   | 日本語 | 時間軸             |
| ------ | ------ | ------------------ |
| Being  | 存在   | 未来志向(期待)     |
| Doing  | 行動   | 今この瞬間(体験)   |
| Having | 所有   | 過去振り返り(結果) |

### Forbes 9セル → 鈴木祐 8つの本能

|                           | Being(存在)              | Doing(行動)           | Having(所有)                     |
| ------------------------- | ------------------------ | --------------------- | -------------------------------- |
| **Intrapsychic(内心的)**  | Security → **安らぐ**    | Identity → **物語る** | Mastery → **進める**             |
| **Instrumental(道具的)**  | Empowerment → **決する** | Engagement → (統合)   | Achievement → **有する**         |
| **Interpersonal(対人的)** | Belonging → **属する**   | Nurturance → (統合)   | Esteem → **高める** / **伝える** |

※ 9→8への変換で、Engagement・Nurturanceは他の本能に統合。Esteemは「高める」「伝える」に分割。

## B4. Dayoptが刺激する本能

### 採用した本能(6つ)

Dayoptは「内心的領域」に特化したツール。以下の6本能を刺激する。

| 優先度     | 本能   | Dayoptでの体験                                   | 対応機能                                                                                               |
| ---------- | ------ | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| **メイン** | 高める | 「見積もり精度が上がっている」という自己効力感   | 見積もり精度の推移(過去の自分との事実比較。gamificationは[strategy.md §4-6](../strategy.md)で永久禁止) |
| **メイン** | 進める | 「守れなかった計画が守れた」という前進の実感     | Plan / Record の突き合わせ、Record のワンタップ確定                                                    |
| サブ       | 決する | 「自分で選んだ時間」という自律感                 | タイムボクシング(自分で1日を設計)、ゴーストのワンタップ確定(選択型ログ)                                |
| サブ       | 物語る | 「自分はこう生きている」という意味               | タグの語彙で1日が構造化される、パターン発見                                                            |
| 補助       | 安らぐ | 「全体感を1箇所で把握できている」という安心感    | 予定と実績が同じタイムラインにある、シンプルなUI                                                       |
| 補助       | 有する | 構造化された時間データという「資産」が蓄積される | 記録の蓄積、MCP/API で自分の AI から参照できる正典データ                                               |

### 採用しなかった本能(2つ)

| 本能       | 不採用の理由                                                                  |
| ---------- | ----------------------------------------------------------------------------- |
| **属する** | Dayoptは個人向けツール。コミュニティ機能なし。「一人で整える」に特化          |
| **伝える** | SNS連携・シェア機能なし。「自分のための記録」であり、他者へのアピールではない |

※ 将来的にコミュニティ機能やシェア機能を追加する場合は再検討

### スコープ外:「没頭(Engagement)」

**判断:Dayoptは「没頭」をサポートしない。** Dayoptは「Before(計画)」と「After(記録)」のツールで、活動中は見ない。没頭を促すリアルタイムのフィードバックは作らない。

**競合との棲み分け:**

| ツール     | フォーカス             | Forbes概念             |
| ---------- | ---------------------- | ---------------------- |
| Forest     | 没頭中(スマホを見ない) | Engagement             |
| Focusmate  | 没頭中(誰かと一緒に)   | Engagement + Belonging |
| Toggl      | 没頭中(タイマー)       | Engagement             |
| **Dayopt** | 没頭後(振り返り)       | Mastery + Security     |

没頭は他ツールに任せる。Dayoptは「没頭できた結果」を記録する。

## B5. Dayoptを好む人の本能プロファイル

### 本能バランスチャート

```
高める ████████████ 強い(自己評価重視。見積もり精度という証拠で確かめたい)
進める ████████████ 強い(前進の実感重視。方法論を回して改善したい)
決する ████████████ 強い(自律性重視。AIに委譲はしても、決定は手放さない)
物語る ████████     やや強い(時間の使い方に整合性・意味を求める)
安らぐ ██████       普通(全体感が見えていれば安心する)
有する ██████       普通(データを資産として蓄積したい。モノへの執着は薄い)
属する ██           弱い(一人で良い。コミュニティは求めない)
伝える ██           弱い(見せるためではなく、自分のために記録する)
```

### 核心的な洞察

> **Dayoptを好む人は「内向きの充実」を求めている**

- 外からの承認(伝える)ではなく、自分の中の証拠(高める)
- みんなと一緒(属する)ではなく、自分で決めた配分(決する)
- 委譲できる作業は AI・ツールに任せ、**時間の使い方の決定と検証だけは自分の手に残す**

## B6. Dayoptが向かない人

| タイプ                     | 理由                                                                         | 代替として向いているツール     |
| -------------------------- | ---------------------------------------------------------------------------- | ------------------------------ |
| **AIに全部決めてほしい人** | Dayoptは配分の決定を自動化しない。「自分で決める」が本質                     | Motion、Reclaim                |
| **属する**が強い人         | コミュニティ機能がない。仲間と一緒にやりたい人には物足りない                 | Habitica、みんチャレ等         |
| **伝える**が強い人         | シェア機能がない。SNSに投稿して「いいね」が欲しい人には向かない              | 公開日記系アプリ               |
| **ご褒美が欲しい人**       | スコア・バッジ・ストリークがない。外発的報酬で動きたい人には物足りない       | ゲーミフィケーション系アプリ   |
| **タスク管理を求める人**   | サブタスク・優先度・期限・ボードは作らない([strategy.md §5](../strategy.md)) | Todoist、Notion、GitHub Issues |

## B7. ターゲット定義

### 分類定義

| 種類               | 定義                                             | 役割                                                 |
| ------------------ | ------------------------------------------------ | ---------------------------------------------------- |
| **戦略ターゲット** | 将来的に広く届けたい理想の利用者層               | 認知拡大・スケーラビリティを前提とした"広い見立て"   |
| **コアターゲット** | 現段階で最も刺さりやすく、利用が期待できる人たち | 最初の共感・継続・課金の中心を担う"具体的なペルソナ" |

### 戦略ターゲット(広義)

> **「時間配分を自分の軸で決め、計画と実績のズレを自分の手で埋めたい個人すべて」**

| 属性     | 内容                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 市場     | 世界中の個人。B2Bではない([strategy.md §3](../strategy.md))                  |
| 状況     | 忙しく、複数のツールに時間データが分断されている                             |
| 意識     | 効率の最大化より、自分の配分への納得感を求める                               |
| 行動特性 | カレンダー・時間記録・タスク管理を試したが、サイクルが回らなかった経験を持つ |

### コアターゲット

> **AI を使いこなす知的労働者**（[strategy.md §3](../strategy.md) を正とする）

- タスク管理・情報整理はすでに AI や既存ツール(GitHub Issues / Notion / Slack)に任せている
- 自分の時間の全体感を見る場所がない — これが唯一残った空白
- 開発者が中核だが、開発者に限らない。創業者自身がアーキタイプユーザー
- Part A のペルソナ像はこのコアターゲットを描いたもの

### 本能トリガー

1. **高める(自尊の改善)** → 見積もり精度が上がっている、という証拠が欲しい
2. **進める(習得の前進)** → 守れなかった計画が守れるようになる前進が欲しい
3. **決する(自由の欲求)** → AI に委譲はしても、時間配分の決定は自分の手に残したい

## B8. コアターゲットの1日(没入ジャーナル)

リモートで働く AI 活用ワーカー(開発者アーキタイプ)の1日。ペインは「怠け」ではなく**見積もりのズレとコンテキストスイッチ**にある。

| 時間帯 | 感情     | 状況           | 何をしているか?                                          | 背景の欲望                       | 本能   |
| ------ | -------- | -------------- | -------------------------------------------------------- | -------------------------------- | ------ |
| 7:00   | 静か     | 自宅           | コーヒーを淹れながら今日の予定を頭の中で組む             | 1日を自分で設計したい            | 決する |
| 8:00   | 前向き   | デスク         | カレンダーとIssueを見比べて今日のブロックを決める        | 段取りを確定させたい             | 決する |
| 9:00   | 集中     | デスク         | 開発ブロック1本目。AI エージェントに調査を並走させる     | 深く進めたい                     | 進める |
| 10:30  | やや焦り | デスク         | 「2時間で終わる」はずの実装がまだ半分                    | 見積もり通りに進めたい           | 進める |
| 12:00  | 中断     | オンライン会議 | 会議が伸びて午後の計画がずれ始める                       | 計画を守りたい                   | 決する |
| 13:00  | リセット | 昼食・散歩     | 午後の計画を頭の中で引き直す                             | 立て直したい                     | 安らぐ |
| 14:00  | 集中     | デスク         | 開発ブロック2本目。Slack通知は切ってある                 | まとまった時間を守りたい         | 進める |
| 16:00  | モヤモヤ | デスク         | レビューと雑務が予定より膨らむ。「今日何やったっけ」     | 時間の行き先を把握したい         | 高める |
| 18:00  | 切り替え | デスク         | 今日の実績を確定して1日を締める                          | 事実で1日を区切りたい            | 高める |
| 20:00  | 内省     | ソファ         | AI チャットに「今週の開発時間、先週と比べてどう?」と聞く | パターンを知って明日に活かしたい | 物語る |
| 22:00  | 落ち着き | 自室           | 明日のブロックを軽く置いて終える                         | 明日を自分の手に置いて眠りたい   | 決する |

このジャーナルが示すこと: ペルソナは**すでに計画を立てている**。欠けているのは意志ではなく、「10:30 のズレ」と「16:00 のモヤモヤ」を翌日の計画精度に変換する装置。

## B9. 共感マップ

**考えていること(Think)**

- 「また見積もりが甘かった。この作業、毎回2倍かかってる気がする」
- 「ツールは揃ってるのに、時間の全体感だけどこにも無い」
- 「Togglみたいな記録はもうやりたくない。でも実績が無いと振り返れない」

**感じていること(Feel)**

- 計画が崩れた日の、原因を特定できないモヤモヤ
- 「忙しかったのに何も進んでない気がする」日への合理的な不満
- 自分の道具は自分で選びたい、というこだわり

**見ているもの(See)**

- GitHub Issues / Notion / カレンダー / AI チャット — データが4箇所に分断されている
- 生産性系ツールの新作は一通りチェックするが、重い・多機能・AI任せで刺さらない

**聞いていること(Hear)**

- 「Motion使えば全部自動だよ」→ 自分で決めたいので響かない
- 「タイムボクシングは理論上最強」→ 知ってる。道具が無いだけ

**主な課題(Pain)**

- 見積もりと実績のズレが記録されず、毎週同じズレを繰り返す
- 記録ツールは入力が重くて続かない。続いても改善に繋がらない
- 計画・実績・分析が別ツールに分断され、サイクルが回らない

**期待する成果(Gain)**

- 作成時に「この作業の実績は45分」と教えてくれて、見積もりがその場で直る
- ワンタップで実績が確定し、記録が儀式として苦にならない
- 構造化された時間データを自分の AI に接続して、横断的な考察ができる
