# メッセージング設計

Dayoptのマーケティングメッセージの核。「何を」「なぜ」伝えるかを定義する。

> プロダクトの最上位コンセプトは [`docs/strategy.md`](../strategy.md) を参照（2026-07-02 策定、本ドキュメントと矛盾する場合は strategy.md を優先）。

---

## 1. ジョブ定義（JTBD）

上位ジョブ・プロダクトの本質は [strategy.md §2](../strategy.md) を正とする（「計画を守れるようにする」）。本節はそれを LP のセクション構成に翻訳する。

### ジョブの階層

| レイヤー         | ジョブ                                             | LPでの役割                |
| ---------------- | -------------------------------------------------- | ------------------------- |
| **上位（Why）**  | 計画を守れるようにしたい                           | HeroのヘッドラインIで語る |
| **中位（What）** | A. 予定と実績のズレを理解したい → 見積もり精度向上 | Problem〜Solutionで展開   |
|                  | B. 時間の配分を自分で決めたい → 主体性             |                           |
|                  | C. 自分のパターンを知りたい → 自己理解             |                           |
| **下位（How）**  | D. 予定と実績を1つの場所で管理したい → ツール統合  | Featuresで見せる          |

### JTBD → LPセクションマッピング

```
上位ジョブ → Hero（ヘッドライン）
中位ジョブ → Problem + Solution
下位ジョブ → Features
```

### 重要な設計原則

- A・B・Cは「なぜそうしたいか（What）」= ユーザーの欲求
- Dは「どうやって実現するか（How）」= 手段のジョブ
- Dを Problem に置くと「道具の話」から始まる → 正しくは上位ジョブから入り、Problemで中位に降りる

## 2. 時間のP/Lメタファー

Dayoptの機能は企業会計と同じ構造を持つ。

| 会計                    | Dayoptでの対応                                            |
| ----------------------- | --------------------------------------------------------- |
| 予算を組む              | タイムボクシングで1日を設計する                           |
| 実績を計上する          | 実際の時間を記録する                                      |
| 決算レポートを読む      | ルールベース統計で振り返る（深掘りはMCP/API経由の外部AI） |
| 損益 = 予算と実績の差分 | 計画と実態のギャップが見える                              |

### 使い方の指針

- **メインメッセージにはしない**（万人に通じない）
- Solution〜Featuresで「なるほど、そういう使い方か」と膝を打たせるメタファーとして投入
- 内部の統計表現（Review画面等）にも応用可能
- 「わかってる人」が深層で共鳴するレイヤー

## 3. 訴求する本能

8つの本能のうち、Dayoptが刺す3つ。いずれも「自分↔自分」の関係で完結し、他者が登場しない。

| 本能       | 意味                         | Dayoptとの対応                                           |
| ---------- | ---------------------------- | -------------------------------------------------------- |
| **進める** | ゴールを設定してクリアしたい | 時間配分の可視化で「今日どれだけ進んだか」が数字で見える |
| **決する** | 自分で決めて実行したい       | タイムボクシング＝「自分で1日を設計する」行為            |
| **高める** | 自分を良くしていきたい       | パターン分析で昨日の自分を超えていく（内向きの成長）     |

参照: [icp.md](./icp.md)

## 4. Before → After

|            | 状態                                                                                   |
| ---------- | -------------------------------------------------------------------------------------- |
| **Before** | 計画は立てるのに守れない。1日が終わって、見積もりのどこがズレたのか説明できない。      |
| **After**  | ズレが毎日の学習になり、見積もりが直る。「立てた計画がその通りに進む日」が増えていく。 |

この変化がDayopt固有の価値。カレンダーは未来だけ、Togglは過去だけ、TODOは完了/未完了だけ。Dayoptだけが「意図と実態を1つの場所で重ねて見る」ことができる（[icp.md §A5](./icp.md) と同一の定義）。

## 6. ブランドパーソナリティ

**ブランドコンセプト**: わかってる人に、ちゃんとした道具を渡す。自分の時間を自分で経営したい人のためのツール。

### キーワード

- **静かに自信がある** — 大げさに煽らない。「自分の時間を自分で決める人のための道具」という落ち着いたスタンス
- **知的だけど冷たくない** — データや数字を扱うけど、目的は自己理解。分析ツールの無機質さではなく、「自分をよく知る」温かみ
- **余白がある** — 詰め込まず、必要なことだけ言う。ユーザーが自分で考える余地を残す
- **対等な目線** — 上から教えるのでも、下から寄り添うのでもない。「わかってる人」に道具を渡す姿勢

### 姿勢

困ってる人に手を差し伸べるのではなく、**「わかってる人に、ちゃんとした道具を渡す」**。

### 基本性格(Big Fiveパーソナリティ)

| 項目       | 特徴                                                  |
| ---------- | ----------------------------------------------------- |
| 誠実性     | 高:時間や記録を守ることに価値を置く                   |
| 開放性     | 中:柔軟だが押し付けない                               |
| 協調性     | 中:寄り添いすぎず、ユーザーの判断を信頼する           |
| 外向性     | 低〜中:必要なときだけ話しかける。余計なことは言わない |
| 神経症傾向 | 低:不安を煽らず、落ち着いた存在                       |

### 差別化軸(他サービスとの違い)

| Dayopt                            | 他ツール(Notion, Todoistなど) |
| --------------------------------- | ----------------------------- |
| 意図と実態を1つの場所で重ねて見る | 計画と記録が別の場所          |
| 計画・実績・分析のサイクル        | 完了/未完了のチェックリスト   |
| 自分の時間を「経営」する道具      | タスクを「管理」するツール    |
| 内向きの充実・自己理解            | 生産性・合理性の最大化        |

### インタラクション原則:「人の気配」を感じさせる

> **コーンって叩いたら、コーンって返ってくる感覚** — note CXO 深津さん

インターネット最大のペインは「頑張ったのに虚空に消える」こと。Dayoptは、ユーザーの行動に対して必ず「こだま」が返る体験を作る。

| 原則             | 説明                                 | 具体例                     |
| ---------------- | ------------------------------------ | -------------------------- |
| **応答性**       | 重要なアクションには必ず反応がある   | ログ記録時のフィードバック |
| **人間の声**     | 機械的でなく「人が話している」感覚   | システムメッセージのトーン |
| **気配の可視化** | 背後に人間がいることを感じさせる     | 過去の自分の記録が見える   |
| **対話感**       | 一方通行でなく、やり取りしている感覚 | 振り返り時の問いかけ       |

| ✅ やること                                        | ❌ やらないこと            |
| -------------------------------------------------- | -------------------------- |
| アクション後に確実なフィードバック（こだま）       | 無言で処理完了             |
| 過去の自分との「再会」を演出                       | データを淡々と表示するだけ |
| 事実で示す進捗（「先週守れなかった計画が守れた」） | 判定・説教・煽り           |
| ユーザーが頼んだ合図だけ鳴らす（opt-in）           | アプリの都合の通知・介入   |

**応答の中身は励ましではなく証拠。** 「がんばりましたね」ではなく「このタグの見積もり精度、4週間前より上がっています」。温かさは声色ではなく、応答が必ず返る確実さと、過去の自分という文脈から生まれる（[strategy.md §4-6, §4-7](../strategy.md) と整合）。

参考: [noteの長く読まれる記事のつくり方と、人のぬくもりを感じるサービスの設計](https://markelabo.com/n/n6185334bfdbf)

### 感性の参考モデル

- **パレオな男**: 習慣化と理屈への理解をベースにした親しみやすさ
- **メンタリストDaigo**: 科学に基づく動機付けの技術
- **note CXO 深津さん**: 人の感情や背景を含めた設計思想

## 7. コアメッセージのLP翻訳

コアメッセージ・ヘッドラインは [strategy.md §2](../strategy.md) で確定済み（"Plan days you can actually keep."）。日本語コピーは次回 LP 作業で確定する。

旧・4候補（Own your time. / Make every hour intentional. / See where your time actually goes. / Your time. By design.）は、いずれも「ズレの可視化」または汎用的な主体性を主訴求にしており、strategy.md の決定と整合しないため不採用。

### RTB（信じられる理由）

「守れる計画」という約束を信じてもらう3つの根拠（旧 value-proposition.md から吸収）:

1. **主体的タイムブロック** — 自分で時間を握るから集中できる
2. **ワンタップ完了 + タグ** — 行動が「見える証拠」になり進捗を確かめられる
3. **ルールベース統計による次週の補正提案** — 記録が次の計画を後押しする（in-app AI ではない。深掘りは MCP/API 経由で自分の AI に接続。[strategy.md §4-8](../strategy.md)）

### 次のアクション

- 日本語ヘッドラインの確定、LP 実装（`apps/web/messages/*.json`）への反映は次回 LP 作業で行う
