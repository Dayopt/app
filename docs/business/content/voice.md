# コンテンツ作成ガイドライン

ブログ・ヘルプ記事・SNS投稿すべてに適用する原則。

---

## 核心原則

> **「AIに評価されたければ、AIが真似できないほど人間臭くあれ」**
> — 深津貴之（note CXO）

AI時代において価値があるのは「あなたにしか言えないこと」。
教科書的な情報はAIが生成できる。Dayoptが発信すべきは、実体験とプロセス。

このガイドは、ブログやSNSなどコンテンツの声（創業者の人間臭い声）の正本である。アプリ内UI文言は、別人格「寡黙な研究者」（正本は[`docs/product/copywriting.md`](../../product/copywriting.md)）で書く。二つの声は意図的な使い分けである。

---

## 6つの原則

### 1. 自社アピールより読者の欲求優先

**NG**: 「Dayoptは〇〇な機能を持つアプリです」（初手で自己紹介）
**OK**: 「時間を記録しても続かない理由、考えたことありますか？」（読者の課題から入る）

読者が知りたいのは「自分の問題がどう解決されるか」。
Dayoptの説明は、それに答えた後で十分。

### 2. 教科書より生々しいエピソード

**NG**: 「タイムトラッキングの5つのメリット」（一般論）
**OK**: 「僕が3回タスク管理に挫折して、なぜ選択型ログに辿り着いたか」（実体験）

- 失敗談
- 迷った過程
- 具体的な数字
- 感情の動き

これらがAIには真似できない価値。

### 3. プロセス > ファクト

**NG**: 「新機能をリリースしました」（結果だけ）
**OK**: 「ユーザーから『〇〇したい』という声があり、3パターン試して、最終的にこの形に決めた理由」（過程を見せる）

各ドメインの `docs/*/log/` に記録している意思決定の過程こそがコンテンツになる。

### 4. 読者の参加を促す

**NG**: 一方的な情報提供で終わる
**OK**: 問いかけ、意見募集、選択肢を示す

```
例）
「みなさんは時間記録、何を基準に振り返っていますか？」
「A案とB案、どちらが使いやすそうですか？」
```

### 5. 継続的な蓄積

単発のバズより、長期的なコンテンツ資産を重視。

- 同じテーマを深掘りする連載
- 過去記事への参照・更新
- 一貫したメッセージの反復

### 6. 誠実さを最優先

- 虚偽のエピソードは絶対NG
- 誇張しない
- わからないことは「わからない」と言う
- 失敗も隠さない

## やらないこと

| NG行為                        | 理由                           |
| ----------------------------- | ------------------------------ |
| AI大量生成スパム              | 価値がない。長期的に検出される |
| Wikipedia的な一般情報のまとめ | AIがやれば十分                 |
| 「続きはアプリで」的な誘導    | 読者体験を損なう               |
| 他サービスの批判              | ブランド毀損                   |
| 過度な宣伝                    | 信頼を失う                     |

---

## Dayoptならではの強み

1人創業者だからこそできる「人間臭さ」を活かす。

Dayoptは「内向きの充実」を求める人のためのツール（参照: [icp.md](../icp.md)）。
この特性と深津氏の提言は相性が良い。

| 強み             | 活かし方                                                |
| ---------------- | ------------------------------------------------------- |
| 意思決定の透明性 | `docs/*/log/` の意思決定ログをコンテンツ化              |
| 顧客との直接対話 | `docs/product/log/*-feedback-*.md` の原文を元にした記事 |
| 開発の裏側       | 技術選定の迷い、失敗談                                  |
| 創業者の思考     | なぜこのプロダクトを作るのか                            |

## 媒体別の適用

### ブログ記事（3本柱）

プロダクトに係る内容を書く。一般論は書かない。各柱が6原則を内包しているため、柱に沿って書けば自動的に原則を満たす。

| 柱                           | 内容                                           | 内包する原則                          |
| ---------------------------- | ---------------------------------------------- | ------------------------------------- |
| **課題起点の開発ストーリー** | 読者の課題 → なぜこう作ったか → 過程と結果     | 1(読者優先), 3(プロセス), 2(生々しさ) |
| **迷いと判断の記録**         | 選択肢A vs B、撤回した判断、失敗から学んだこと | 6(誠実), 2(生々しさ), 3(プロセス)     |
| **問いかけと連載**           | 読者への問い、同テーマの深掘り、過去記事の更新 | 4(参加促進), 5(蓄積), 1(読者優先)     |

### ヘルプ記事

- 機能説明 + 「なぜこの設計にしたか」
- よくある質問 + 「この質問が多い背景」
- Tips + 「実際のユーザーの使い方例」

### SNS投稿

- 開発の裏側（迷い、選択、学び）
- ユーザーとの対話
- 問いかけ形式の投稿

※ SNS運用の詳細は [`channels/x.md`](../channels/x.md) と [`channels/reddit.md`](../channels/reddit.md) を参照
