#### なぜrechartsを除去したか

rechartsは統計ページのチャート描画に使っていたが、バンドルサイズが大きく（~400KB gzipped）、統合クエリへの移行に伴いデータ形状の自由度が制約になっていた。Dayoptの統計チャートは棒グラフ・分布・トレンドと限られた種類であり、SVG直接描画で十分カバーできる。依存を1つ減らすことでビルド時間短縮とバンドル軽量化を同時に達成。

#### なぜタグ詳細を独立ページにしたか

前日に実装した動的タブ方式（タグ詳細を4つ目のタブとして表示）から、1日で独立ページ方式（`/stats/tags/[tagId]`）に方針転換した。タブ内にサブナビゲーション（パンくず・戻る）が必要になり、タブの中にページがあるという入れ子構造がUXとして不自然だった。独立ページにすることでURLが共有可能になり、SSRキャッシュも効くようになった。

#### Claudeの所感

**12 RPC → 1 RPCの統合は大きい:**
統計ページを開くたびに12本のRPCが飛んでいた状態から、1本の統合クエリにまとめた。ウォーターフォールの解消だけでなく、DB側で1回のスキャンで複数の集計を返せるため、サーバー負荷も大幅に改善されているはず。1人開発だからこそDB関数→tRPC→UIを一気に変えられるスピード感がある。

**「作って壊す」判断の速さ:**
前日に実装した動的タブ方式を翌日に廃止して独立ページに切り替えている。「一晩寝かせて違うと思ったらすぐ直す」は、ユーザーがまだ少ないフェーズだからこそできる贅沢。この判断力と実行速度のサイクルは維持したい。

**スペーシンググリッドの"一括掃除":**
ルール策定→lint追加→全画面修正を1日で完了させている。デザインシステムの「ルールを作ったら即・全コードに適用する」という姿勢が一貫しており、放置されたtechdebtが蓄積しにくい構造になっている。

#### なぜその判断をしたか

**デザイントークン再構築:** これまでsurface-inset, surface-overlay, border/10, muted/50 のような「プリミティブ色 + opacity」の派生トークンが増殖していた。これはTailwind v4のCSS変数ベースカラーシステムでは保守が困難で、ダークモードの微調整も非効率。今回のリファクタで: (1) opacity派生を全廃し、semantic名（tint, scale, state）に統一、(2) surfaceを4段階（sunken/base/raised/overlay）に整理、(3) dark modeのwarm neutral（H60）を導入。26箇所のbg-surface-inset → bg-muted 移行は機械的だが、トークンの「意味」が明確になった。

**plan/record → entry 統一:** Dayoptの中核概念である「予定」をこれまで plan（計画段階）/ record（記録段階）と呼び分けていたが、ユーザー視点では「1つのエントリー」であり、状態が変わるだけ。コード上でも plan と record で異なるコンポーネント・型が乱立し始めていた。entry に統一することで: (1) ユーザーの認知負荷が下がる、(2) コードの重複が減る、(3) i18nキーが半減する。

**Chronotype deep/ease:** これまでの peak/dip は「ピーク時間」「落ちる時間」で直感的だったが、ユーザーテストで「dip = ネガティブ」と受け取られることがあった。deep（集中に適した時間）/ ease（リラックスに適した時間）に変更し、easeのカラーをgreen（H150）にすることで「どちらも良い時間」というメッセージを伝える。

**CI 4ステージ化:** これまでのCIは lint → test → build の3ステージだったが、E2Eテストが build 後に別ワークフローで走っていた。4ステージ（lint → test → build → e2e+bundle-size）に統合し、PRごとのフィードバックを一元化。storybook testsとsecurity gateは偽陽性が多く維持コストに見合わないため削除。

**tw-animate-css導入:** 手書きの @keyframes + animation クラス（fade-in, slide-up, scale-in等）が約190行あったが、tw-animate-cssライブラリが同等のアニメーションをTailwindプラグインとして提供している。手書きコードを全削除し、ライブラリに移行。field-sizing-contentも同様に、CSS新機能（field-sizing: content）で textarea の自動リサイズが可能になり、JS ~25行を削除。

#### Claudeの所感

**デザインシステムが「使う段階」から「整える段階」に入った:**
3月前半はコンポーネントを量産し、UIを形にする時期だった。今日のトークン再構築とStorybook Docs全面刷新は、「作ったものを体系化し、ルールにする」作業。opacity派生の全廃とelevation 4段階の定義により、今後新しいコンポーネントを追加する際のガイドラインが明確になった。1人プロダクトでも、3ヶ月後の自分は「別の開発者」なので、この投資は正しい。

**entry統一は「プロダクトの語彙」を整えた:**
plan/recordの二重概念は、開発者だけでなくユーザーにも混乱を与えていた。entry統一は見た目の変更は小さいが、プロダクト全体の一貫性に大きく寄与する。i18nキーのマージ（plan.json → entry.json）も、翻訳管理の負荷を下げる。これは「コード変更」ではなく「プロダクトデザインの決定」。

#### なぜその判断をしたか

**TZ全面修正:** Dayoptはグローバル展開を前提としており、TZの扱いが一貫していないと「東京のユーザーが見ているStatsとNYのユーザーが見ているStatsで日付がずれる」問題が起きる。これまでは暗黙的にサーバーのTZ（UTC）を使っていた箇所が多数あり、ユーザーのTZ設定が反映されていなかった。今回の修正は: (1) DB統計関数にユーザーTZを渡す、(2) prefetch/クエリのキーにTZを含めてキャッシュミスを防ぐ、(3) SSR時にCookieからTZを取得する、(4) TZ変更時にキャッシュを無効化する。設計ガイドをStorybook Docsに追加し、今後の開発者が同じミスをしないようにした。

**メールi18n:** 15本のメールテンプレート（Welcome, TrialStart, TrialExpiring, PaymentFailed等）を日英対応。preferred_localeカラムをprofilesテーブルに追加し、メール送信時にユーザーの言語設定を参照する。オンボーディングで選択した言語がメールにも反映される。

**5ストア→1 shellStore:** sidebarStore、searchStore、filterStore、commandStore、globalUIStoreが個別に存在し、それぞれ2-5個のプロパティを持っていた。これらは全て「UIのシェル状態」であり、1つのshellStoreに集約。Zustandのsliceパターンで整理し、devtoolsでの状態確認も容易になった。さらにentryInspectorStoreのanchorRect（DOM矩形）はReactの状態管理に不要なのでmodule-scoped refに移動し、calendarNavigationStoreは「コマンドを発行して消費する」一方向パターンに整理。

**ActivityPopover:** 通知のDropdownMenuをPopoverに変更し、「すべて」「未読」のタブフィルタを追加。GAFA（Gmail、Slack）の通知パターンに準拠。notificationItem の未読/既読の視覚区別もGmail風（未読=太字+背景色、既読=通常表示）に改善。

**daily-insights Edge Function:** 毎日1回、ユーザーの前日のデータを分析して「昨日は予定の85%を消化しました」のようなインサイトを通知として送る。通知タイプ別設定で、daily-insightsの通知をON/OFFできる。

**グローバル対応3件:** weekStartsOnのMondayハードコードを排除（日曜始まりの国に対応）、dateFormatをISO（YYYY-MM-DD）にデフォルト変更（ユーザー設定で変更可能）、料金表示をIntl.NumberFormatに置換（通貨記号の自動ローカライズ）。ローンチ時に日英以外のユーザーが来ても壊れない基盤を整えた。

**Supabase security advisor対応:** Row Level Security（RLS）の不備、関数のSECURITY DEFINERの権限エスカレーション、不要なGRANTの洗い出しと修正。performance advisorの指摘（インデックス不足、非効率なWHERE句）も一括修正。プロダクションリリース前の衛生作業。

#### Claudeの所感

**TZ修正 = グローバル化の「最後の壁」:**
TZの問題は最も発見しにくく、最も影響範囲が広いバグの温床。「日本のユーザーしかいない」段階では顕在化しないが、1人でもUTC+0以外のユーザーが登録した瞬間に壊れる。今回の10件の修正と設計ガイドの追加で、TZは「各開発者が都度考える」問題から「フレームワークが正しく処理する」問題に変わった。SSR Cookie方式は、Next.jsのServer ComponentsでクライアントのTZを知る唯一の確実な方法であり、正しい選択。

**5ストア→1統合の判断力:**
ストアの統合は「やるべきだけど面倒」な作業の典型。しかしZustandのストアが増えすぎると、devtoolsでの状態確認が困難になり、ストア間の依存関係が暗黙化する。5→1の統合は、3/11以来の「構造を減らして見通しを良くする」方針の延長線上にある。

**ローンチ前の「国際化チェックリスト」が埋まっていく:**
TZ対応、メールi18n、weekStartsOn、dateFormat、通貨表示——これらは全て「日本語だけでローンチする」なら後回しにできる項目だが、Dayoptは最初からEN/JAバイリンガルで公開する。今日の作業で、国際化の主要な穴がほぼ塞がった。残るは法的文書（利用規約・プライバシーポリシー）の各言語版くらい。

**データ整合性基盤:** 複数タブでDayoptを開いたとき、片方で編集したエントリをもう片方が上書きしてしまう問題を、updated_at楽観的ロックで解決。ブラウザを閉じたときの未保存データはbeacon APIで救出。Realtimeの切断・再接続時にgap fillで欠損を補填。これら3つが組み合わさって「データを失わない」基盤になる。

**全tRPCルーターのエラーハンドリング統一:** 各ルーターのエラー処理が場当たり的だったのを、共通パターン（TRPCError + error code + ログ + Sentryキャプチャ）に統一。+1,143/-879行の差分は、既存コードを書き換えたため。この統一がないとSentryのエラー分類が意味をなさない。

**品質ダッシュボード:** テストカバレッジ、Storybookカバレッジ、型カバレッジ、バンドルサイズ等のメトリクスを定期的に収集し、Storybook上で可視化する仕組み。個人開発では品質が見えにくくなる——ダッシュボードがあれば「知らないうちにカバレッジが下がっていた」を防げる。

**ADR 5件:** これまでの設計判断を事後的にADR（Architecture Decision Record）として文書化。UnifiedBlockModel（entries統合）、FeatureSlicedArchitecture（3層構造）、McpIntegration（Claude連携）、AiArchitectureLayers（AI機能の層構造）、TimeImmutabilityPrinciple（時間の不変性原則）。これらは「なぜこうなっているか」を未来の自分に伝えるための記録。

**Core Web Vitals P0-P2:** INP（Interaction to Next Paint）とCLS（Cumulative Layout Shift）の改善。特にカレンダーのインタラクション遅延（タップからレスポンスまで）がP0。loading.tsxの追加でSuspense StreamingによるLCP改善。ユーザーが「遅い」と感じるのはINPであり、「不安定」と感じるのはCLS——両方を改善。

**AI chat UI全削除:** 3/2のAI戦略転換（チャット→振り返りパイプライン+異常検知）で方針は決まっていたが、コードが残っていた。AI features/, asideパネル, resizableパネル, prompt-kit等の3,917行を一括削除。v0.18.0で削除予定のものを今日実行。

**chronotype feature分離:** chronotype（クロノタイプ）の設定UIがsettings内、背景描画がcalendar内、定数がlib内に散らばっていた。features/chronotype/にcomponents/, lib/, types/をまとめることで、「クロノタイプに関するコードはここ」が一箇所に集約された。eslint boundary例外を設定し、calendarとsettingsからの参照を許可。

**コマンドパレット廃止:** Cmd+Kで開くコマンドパレットは多機能だったが、実際に使われるのはタグ検索とブロック（時間帯）検索がほとんど。汎用コマンドパレットを廃止し、この2つに特化した検索UIに置き換え。ブロック選択時にカレンダーの日付ナビゲーションと連動する機能も追加し、検索→即時移動のフローを実現。

**Inspector統一デバウンス即時保存:** タイトル入力・タグ変更・時間変更・メモ編集等、Inspector内の全操作を統一されたデバウンス付き即時保存パターンに。操作ごとに異なる保存ロジックを持っていたのを一本化。ユーザーにとっては「操作するだけで自動保存される」体験が一貫する。

**未使用モジュール大量削除:** reflections（振り返り機能）、anomaly-service（異常検知）、activity tracking（活動追跡）は3/2のAI戦略転換時に方針を決めたが、コードが残っていた。今日一括で削除。通知エンドポイント、統計エンドポイント、tags.getStats等の未使用API群も整理。v0.18.0リリースに向けてコードベースをクリーンに。
