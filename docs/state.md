## やらないこと・止めること

- **開発体制の増築** — 評議会・常任席・新しい定例・新しい正本文書。役割は 3 つ（メタ把握 / 指揮 / レーン）以上に増やさない
- **ChatGPT を体制へ組み込むこと** — 外部の目が欲しい時に読ませるのは自由だが、規約化しない（規約化すると維持対象になる）
- **AI 間の合意を証拠として扱うこと** — 判断を更新するのは test / code / log / User の実測だけ
- **メタシステムの散文を無制限に増やすこと** — ルールを 1 つ足すなら 1 つ削る

## 前提（崩れたら見直す）

- **FACT** — merge / review / CI の手続きは機械が強制している（hooks / `branch:finish` / CI 4 層）。指揮の質はこの機械層の上でのみ問われる
- **FACT** — 2026-09 に repo を private 化する。Actions 無料枠が予算制約として復活する
- **INTERPRETATION** — 指揮台の価値の大半は手続きではなく収束判定（レビュー往復の打ち切り）と矛盾報告の独立再検証にある。だからこの 2 つだけは escalation 条件として残した
- **BET** — 開発体制の複雑さは、それ自体がプロダクトの速度を殺しうる。ここ 1 か月の issue が ops / orchestration に偏っているのはその兆候として扱う
