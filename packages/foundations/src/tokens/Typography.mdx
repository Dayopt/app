# Typography

フォントサイズは Tailwind のデフォルトスケールをそのまま使用。業界標準で学習コストゼロ。

---

## 原則

- **サイズの差**で重要度を表現（大きい = 重要）
- **ウェイト**で強調（bold = 見出し、normal = 本文）
- **色**で階層（`text-foreground` = 主要、`text-muted-foreground` = 補助）→ 詳細は [Colors](?path=/docs/foundations-colors--docs)
- **書体は Adobe Source ファミリーの3つだけ**（下記）、next/font で最適化済み

---

## フォントファミリー

使うのは3書体だけ。Adobe Source ファミリーで統一している。

| 役割     | 書体                | クラス      | next/font 変数   | 用途                                            |
| -------- | ------------------- | ----------- | ---------------- | ----------------------------------------------- |
| **欧文** | **Source Sans 3**   | `font-sans` | `--font-latin`   | 本文・UI テキスト全般（ラテン文字）             |
| **和文** | **Noto Sans JP**    | `font-sans` | `--font-noto-jp` | 本文・UI テキスト全般（日本語）                 |
| **等幅** | **Source Code Pro** | `font-mono` | `--font-code`    | 時刻・duration・統計の数字、エラーID、MFAコード |

### なぜ Source ファミリーか

Noto Sans JP は、Google が Noto ブランドで再配布している **Adobe Source Han Sans と同一**。
そのため欧文を Source Sans 3 にすると、3書体すべてが同じ血筋になり、和欧混植の行に継ぎ目が出ない。
実績のある和文の可読性は変えずに、ファミリーの一貫性だけを得られる。

等幅も同じファミリーに揃えるのは、時刻・duration・統計の数字が Dayopt の主役だから。
桁を揃えて読み比べるため `font-mono` と `tabular-nums` を併用する。

### 読み込みの構成

- 書体の実体は各アプリの **next/font** が読み込む。stack の合成は `packages/foundations/src/tokens/typography.css` が正本
- Tailwind への接続は `tailwind-theme.css` の `@theme inline`。`font-sans` と `font-mono` だけを上書きしている
- body と `font-sans` utility は同じ stack を参照する（stack を複製しない）
- Source Code Pro は `preload: false`。本文に使わないので LCP を優先する
- Storybook は next/font を通らないため `.storybook/main.ts` が同じ変数名を手動定義している。**変数名を変える時は両方直す**（片方だけだと黙ってシステムフォントに落ちる）

> 実際の字面・和欧混植・数字の見本は Storybook の **FontFamily** ストーリーで確認できる。

## フォントサイズスケール

| クラス      | サイズ | 用途                       | 備考         |
| ----------- | ------ | -------------------------- | ------------ |
| `text-xs`   | 12px   | タイムスタンプ、注釈       | **よく使う** |
| `text-sm`   | 14px   | UIテキスト、ボタン、ラベル | **よく使う** |
| `text-base` | 16px   | 本文（デフォルト）         | **よく使う** |
| `text-lg`   | 18px   | 小見出し                   |              |
| `text-xl`   | 20px   | カード見出し               |              |
| `text-2xl`  | 24px   | セクション見出し           | **よく使う** |
| `text-3xl`  | 30px   | ページタイトル             |              |
| `text-4xl`  | 36px   | ヒーロー                   |              |

## タイポグラフィ階層

UIで使う典型的なパターン。

| 用途             | クラス                          |
| ---------------- | ------------------------------- |
| ページタイトル   | `text-2xl font-medium`          |
| サブテキスト     | `text-sm text-muted-foreground` |
| セクション見出し | `text-lg font-medium`           |
| カード見出し     | `font-medium`                   |
| フォームラベル   | `text-sm font-medium`           |
| 補助テキスト     | `text-xs text-muted-foreground` |

---

## フォントウェイト

2つだけ。シンプルに保つ。

| クラス        | Weight | 用途                                         |
| ------------- | ------ | -------------------------------------------- |
| `font-medium` | 500    | 見出し、ラベル、強調、stat値                 |
| `font-normal` | 400    | 本文テキスト（段落、説明文、UIテキスト全般） |

**禁止**: font-bold, font-semibold, font-extrabold, font-black, font-light, font-thin

---

## 行間

| 用途   | クラス            | 値    |
| ------ | ----------------- | ----- |
| 見出し | `leading-tight`   | 1.25  |
| 本文   | `leading-normal`  | 1.5   |
| 長文   | `leading-relaxed` | 1.625 |

## Do's & Don'ts

### Tailwind デフォルトスケールを使用

```tsx
// ✅ Do
<h1 className="text-2xl font-medium">見出し</h1>
<p className="text-base">本文</p>
<span className="text-sm text-muted-foreground">補助</span>

// ❌ Don't — 任意値は禁止
<h1 className="text-[23px] font-medium">見出し</h1>
<p className="text-[15px]">本文</p>
```

理由: 業界標準のスケールで一貫性を保ち、デザインの統一感を維持。

### 階層的なサイズ変化

```tsx
// ✅ Do — 1段階ずつ下げる
<h1 className="text-xl font-medium">見出し1</h1>
<h2 className="text-lg font-medium">見出し2</h2>
<p className="text-base">本文</p>

// ❌ Don't — サイズが飛びすぎ
<h1 className="text-3xl font-medium">見出し1</h1>
<h2 className="text-sm font-medium">見出し2</h2>
<p className="text-xs">本文</p>
```

理由: 視覚的階層が崩れ、情報の重要度が伝わりにくくなる。

### ウェイトは2種類まで

```tsx
// ✅ Do
font-medium（見出し、強調）
font-normal（本文）

// ❌ Don't — font-bold, font-semibold, font-extrabold, font-black, font-light, font-thin
```

理由: ウェイトの多用は視覚的ノイズになり、本当に強調したい部分が埋もれる。

### テキスト色で階層を表現

- ✅ `text-foreground`（主要）、`text-muted-foreground`（補助）
- ❌ `text-gray-600`（直接色指定）、`text-foreground/50`（透明度）

> 色のルール全般は [Colors → Do's & Don'ts](?path=/docs/foundations-colors--docs) を参照。
