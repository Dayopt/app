# カラートークン

tokens/colors.css のセマンティックトークン一覧。Tailwind クラス名でそのままコピペ可能。

> **2層構造**: Primitives（原液） → Semantic（役割）。
> Hue定数やNeutralスケールは [Foundations/Primitives](?path=/docs/foundations-primitives--docs) を参照。

---

## Surface（背景色・MD3準拠4段階）

Material Design 3 に基づく意味ベース設計。
ダークモードでは高 elevation = 明るい（MD3 原則）。明度差は 3-6% で視認性を確保。

| トークン | MD3 | 用途 |
|----------|-----|------|
| `bg-background` | Surface | ページ背景（基準レベル） |
| `bg-surface-inset` | Container Low | card内セクション（background より 3% 暗い） |
| `bg-container` | Container | サイドバー、セクション（inset より 3% 暗い） |
| `bg-card` | Container High | カード、ダイアログ、ポップオーバー（container より 3% 暗い） |
| `bg-overlay` | — | モーダル背景（半透明・MD3 scrim） |

## Semantic（意味を持つ色）

WCAG 2.1 AA 準拠。全ペアが card 背景上で 4.5:1+ のコントラスト比を確保。
ダークモードでは明度を上げ、foreground をダーク文字に反転して対応。

| トークン | 色 | 用途 |
|----------|-----|------|
| `bg-destructive` / `text-destructive-foreground` | 赤 (hue 25) | 削除、エラー |
| `bg-warning` / `text-warning-foreground` | amber (hue 68) | 警告、注意 |
| `bg-success` / `text-success-foreground` | 緑 (hue 149) | 成功、完了 |
| `bg-info` / `text-info-foreground` | 青 (hue 250) | 情報、ヒント |

### ダークモードの foreground 反転

ダークモードではセマンティックカラーの明度が上がるため、foreground を白→ダーク文字に反転。
`text-{semantic}-foreground` は自動で切り替わるため、コンポーネント側の変更は不要。

## Chronotype（エネルギーフェーズ）

> **温度グラデーション設計**: 高エネルギー=暖色(amber)→低エネルギー=寒色(indigo)。
> 覚醒時のエネルギー周期を 5 フェーズ（warmup→peak→dip→recovery→winddown）で表現。

| トークン | Hue | 用途 |
|----------|-----|------|
| `bg-chronotype-warmup` | 145 (green) | ウォームアップ（起床後） |
| `bg-chronotype-peak` | 85 (amber) | ピーク（最集中） |
| `bg-chronotype-dip` | 250 (blue) | ディップ（エネルギー低下） |
| `bg-chronotype-recovery` | 200 (cyan) | リカバリー（回復） |
| `bg-chronotype-winddown` | 280 (indigo) | ウインドダウン（就寝準備） |

### Tints（タイムライン背景用）

> 不透明度ルールの例外: base 色の H を共有しつつ L/C/alpha を導出。
> Light: L=0.50, α=0.10-0.18 / Dark: L=0.70, α=0.05-0.13

| トークン | 用途 |
|----------|------|
| `bg-chronotype-tint-warmup` | ウォームアップ背景 |
| `bg-chronotype-tint-peak` | ピーク背景 |
| `bg-chronotype-tint-dip` | ディップ背景 |
| `bg-chronotype-tint-recovery` | リカバリー背景 |
| `bg-chronotype-tint-winddown` | ウインドダウン背景 |

## Do's & Don'ts

### セマンティックトークンを使用

```tsx
// ✅ Do
<div className="bg-destructive text-destructive-foreground">エラー</div>
<div className="bg-success text-success-foreground">成功</div>

// ❌ Don't — 直接色指定
<div className="bg-red-500 text-white">エラー</div>
<div className="bg-green-500 text-white">成功</div>
```

理由: セマンティックトークンはダークモード対応を自動化し、デザイン変更時の一括修正を可能にする。

### 適切なテキストコントラスト

```tsx
// ✅ Do
<div className="bg-primary text-primary-foreground">正しい組み合わせ</div>

// ❌ Don't — 低コントラスト
<div className="bg-primary text-muted-foreground">読みにくい</div>
```

理由: WCAG 2.1 AA 基準（コントラスト比 4.5:1 以上）を満たすため。

### Surface 階層を守る

```
✅ background → surface-inset → container → card（親→子で暗くなる）
❌ card → background → container（逆転）
```

理由: MD3 原則に基づく視覚的階層。card内のセクションには `bg-surface-inset` を使用。

### 状態を色で表現

- ✅ 成功 → `text-success`、エラー → `text-destructive`、警告 → `text-warning`、情報 → `text-info`
- ❌ 成功を青で表示、エラーを黄色で表示、色だけで状態を伝える（アイコンなし）

---

## 色覚多様性への配慮（WCAG 1.4.1）

色だけで情報を伝えない。必ずアイコン・テキスト・形状を併用する。

```tsx
// ✅ Do — 色 + アイコン + テキストの三重伝達
<Badge variant="success"><CheckCircle2 /> 完了</Badge>
<Badge variant="destructive"><XCircle /> エラー</Badge>

// ❌ Don't — 色のみで状態を伝える
<span className="text-success">完了</span>  // 色盲ユーザーが識別困難
```

赤/緑の組み合わせのみで対比しない（protanopia/deuteranopia 対策）。
