# Rule Insights

閾値ベースの自動気づき生成。Layer 1 の一部として、メトリクス数値の「解釈」をルールで自動化する。LLM 不要。

---

## 位置づけ

```
Layer 1 (自動計算)
├── KPI メトリクス 8カード     ← 既存
└── Rule Insights              ← ここ（閾値ベースの気づき）
```

- **Layer 1.5 ではない** — Layer 1 の一部
- **LLM 不要** — 純粋関数で判定
- **配置予定**: Review タブ（KPI グリッドの下）

---

## インターフェース

```typescript
interface RuleInsight {
  metricId: MetricId;
  type: 'threshold' | 'trend' | 'anomaly';
  severity: 'info' | 'warning' | 'critical';
  message: string;       // "Plan Rate が先週より 20% 低下しました"
  detail?: string;       // "計画時間を2時間ブロックしてみましょう"
}

type MetricId =
  | 'totalTime'
  | 'avgFulfillment'
  | 'planRate'
  | 'streak'
  | 'estimationAccuracy'
  | 'deepUtilization'
  | 'contextSwitches'
  | 'blankRate';
```

---

## ルール例

### 閾値ルール（threshold）

| 条件 | severity | message |
|------|----------|---------|
| Plan Rate < 50% | warning | "今週の活動の大半は計画外でした" |
| Deep Utilization < 30% | info | "ピーク時間帯がほとんど使われていません" |
| Context Switches > 8/日 | warning | "タスク切替が多い週でした" |
| Blank Rate > 60% | info | "空白時間が多めの週でした" |

### トレンドルール（trend）

| 条件 | severity | message |
|------|----------|---------|
| 前期間比 20% 以上悪化 | warning | "{メトリクス} が大きく低下しました" |
| 前期間比 20% 以上改善 | info | "{メトリクス} が大きく改善しました" |
| 3期間連続悪化 | warning | "{メトリクス} が連続して低下しています" |

### 異常検知ルール（anomaly）

| 条件 | severity | message |
|------|----------|---------|
| Total Time が平均の 2倍超 | info | "記録時間が通常より多い週でした" |
| Streak 途切れ | info | "連続記録が途切れました" |

## 実装

### 純粋関数

```typescript
// src/features/stats/lib/ruleInsights.ts
function evaluateRuleInsights(
  currentMetrics: MetricValues,
  previousMetrics: MetricValues | null,
  thresholds?: Partial<RuleThresholds>,
): RuleInsight[]
```

- **入力**: 現在と前期間のメトリクス値
- **出力**: 発火したルールの配列（severity 降順）
- **閾値**: デフォルト値あり、将来的にユーザーカスタマイズ可能
- **テスト**: 全ルールのユニットテスト必須

### デフォルト閾値

```typescript
const DEFAULT_THRESHOLDS: RuleThresholds = {
  planRate: { low: 0.5 },
  deepUtilization: { low: 0.3 },
  contextSwitches: { high: 8 },
  blankRate: { high: 0.6 },
  trendDelta: 0.2,           // 20% 変化で発火
};
```

## トーン

Dayopt の「観察者（watching AI）」哲学に従う:

- 事実を淡々と伝える
- 励ましやモチベーション向上の言葉は使わない
- "改善しましょう" ではなく "低下しました"
- detail（提案）は具体的で行動可能なもののみ

## UI コンポーネント

### RuleInsightList

Review タブの KPI グリッド下に配置。発火したルールをリスト表示。

```
┌──────────────────────────────────────┐
│ ⚠ Plan Rate が先週より 20% 低下     │
│   計画時間を2時間ブロックしてみま... │
├──────────────────────────────────────┤
│ ℹ ピーク時間帯がほとんど使われて...  │
└──────────────────────────────────────┘
```

- severity で色分け（warning: amber, info: muted, critical: red）
- 0件の場合は非表示（特に何も問題がない = 表示不要）
- 最大 3件まで表示（severity 順でカット）

## Layer 3 との違い

| | Rule Insights | LLM Insights |
|---|---|---|
| **計算** | 閾値判定（純粋関数） | LLM 推論 |
| **コスト** | 0 | ~$0.004/回 |
| **リアルタイム性** | 即座 | pg_cron スケジュール |
| **粒度** | 単一メトリクスごと | 複数メトリクスの総合分析 |
| **カスタマイズ** | 閾値調整 | communication style |

Rule Insights は「今すぐ見える数値の解釈」、LLM Insights は「期間全体の文脈を踏まえた洞察」。
