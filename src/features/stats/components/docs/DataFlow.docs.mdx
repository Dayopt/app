# Data Flow

Stats feature のデータ取得・変換・表示のパイプライン。

---

## 全体像

```
PostgreSQL RPC 関数
  → tRPC ルーター (entry/stats feature)
    → TanStack Query (並列取得・自動キャッシュ)
      → 純粋計算関数 / Recharts
        → UI コンポーネント
```

Layer 3 のみ異なるパス:

```
PostgreSQL RPC 関数
  → Edge Function (pg_cron 定期実行)
    → Anthropic API
      → reflections テーブルに保存
        → tRPC (insights ルーター)
          → UI コンポーネント
```

---

## tRPC エンドポイント

### Layer 1: KPI メトリクス

**ルーター**: `src/features/entry/server/statistics.ts`

| エンドポイント          | Input                  | 説明                      |
| ----------------------- | ---------------------- | ------------------------- |
| `getCumulativeTime`     | dateRange              | 期間内の記録時間合計      |
| `getStreak`             | —                      | 連続アクティビティ日数    |
| `getPlanRate`           | dateRange              | 計画率                    |
| `getEstimationAccuracy` | dateRange              | タグ別見積もり精度        |
| `getEnergyMap`          | dateRange              | 時間帯×曜日エネルギー分布 |
| `getContextSwitches`    | dateRange              | タスク切替回数            |
| `getBlankRate`          | dateRange + wake/sleep | 空白時間率                |

### Layer 2: チャート

**ルーター**: `src/features/entry/server/statistics.ts`

| エンドポイント             | Input         | 説明                   |
| -------------------------- | ------------- | ---------------------- |
| `getDailyHours`            | `{ year }`    | ヒートマップ用日次集計 |
| `getMonthlyTrend`          | `{ months? }` | 月次推移               |
| `getDayOfWeekDistribution` | dateRange?    | 曜日別分布             |
| `getHourlyDistribution`    | dateRange?    | 時間帯分布             |

### Layer 3: インサイト

**ルーター**: `src/features/stats/server/insights-router.ts`（新規）

| エンドポイント          | Input                              | 説明                     |
| ----------------------- | ---------------------------------- | ------------------------ |
| `insights.getInsight`   | `{ periodType, periodStart }`      | 特定期間のインサイト取得 |
| `insights.listInsights` | `{ periodType?, limit?, cursor? }` | インサイト一覧           |
| `insights.updateNote`   | `{ insightId, userNote }`          | ユーザーメモ更新         |

## 状態管理

### useStatsFilterStore (Zustand)

| State         | 型                                     | 説明                 |
| ------------- | -------------------------------------- | -------------------- |
| `granularity` | `'day' \| 'week' \| 'month' \| 'year'` | 表示粒度             |
| `currentDate` | `Date`                                 | ナビゲーション基準日 |

### タブ状態

URL がソース・オブ・トゥルース（`/stats/review`, `/stats/progress`, `/stats/insights`）。`pushState` によるクライアントサイド遷移。

---

## キャッシュ戦略

- Layer 1/2: TanStack Query の staleTime でキャッシュ。粒度・日付の組み合わせがキャッシュキー
- Layer 3: reflections テーブルに永続保存済み。tRPC 経由で取得、staleTime: Infinity（期間のインサイトは不変）

---

## DB 集約関数

### get_insights_data()

Layer 3 の Edge Function 用。1 回の呼び出しで L1 + L2 の全データを返す。

```
返却データ:
├── Layer 1 KPIs (totalMinutes, avgFulfillment, planRate, ...)
├── Layer 2 Patterns (hourly/dayOfWeek distribution, tagBreakdown)
├── Chronotype 分析 (phaseBreakdown)
├── 前期間比較 (prev_totalMinutes, prev_avgFulfillment, ...)
└── メタ (daysWithEntries, daysInPeriod, fulfillmentCoverage)
```

### get_user_settings_for_insights()

ユーザー設定から LLM プロンプトに必要な情報を取得。

→ chronotype_type, personalization_values, ai_communication_style, timezone
