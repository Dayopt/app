# メッセージング設計

Dayoptのマーケティングメッセージの核。「何を」「なぜ」伝えるかを定義する。

---

## 1. プロダクトの本質

Dayoptはタイムボクシングによるスケジュール配分ツール。カレンダーでもタスク管理でもない。

- 1つのエントリが「意図」と「実際」を兼ねる（plan/record統合）
- 過去も未来も同じように自由に編集できる
- パターン検出・統計・AIによるインサイト
- 「自分の時間の使い方」を可視化する

---

## 2. ジョブ定義（JTBD）

### 上位ジョブ（Why）

**自分の時間を、計画・実績・分析のサイクルで回したい。自分の時間の使い方を自分でコントロールするために。**

→ Dayoptは「自分の時間を経営する」ためのツール。

### ジョブの階層

| レイヤー         | ジョブ                                             | LPでの役割                |
| ---------------- | -------------------------------------------------- | ------------------------- |
| **上位（Why）**  | 自分の時間の使い方を自分でコントロールしたい       | HeroのヘッドラインIで語る |
| **中位（What）** | A. 実際に何に時間を使ったか見たい → 改善の手がかり | Problem〜Solutionで展開   |
|                  | B. 時間の配分を自分で決めたい → 主体性             |                           |
|                  | C. 自分のパターンを知りたい → 自己理解             |                           |
| **下位（How）**  | D. 予定と実績を1つの場所で管理したい → ツール統合  | Featuresで見せる          |

### JTBD → LPセクションマッピング

```
上位ジョブ → Hero（ヘッドライン）
中位ジョブ → Problem + Solution
下位ジョブ → Features
```

### 重要な設計原則

- A・B・Cは「なぜそうしたいか（What）」= ユーザーの欲求
- Dは「どうやって実現するか（How）」= 手段のジョブ
- Dを Problem に置くと「道具の話」から始まる → 正しくは上位ジョブから入り、Problemで中位に降りる

---

## 3. 時間のP/Lメタファー

Dayoptの機能は企業会計と同じ構造を持つ。

| 会計                    | Dayoptでの対応                  |
| ----------------------- | ------------------------------- |
| 予算を組む              | タイムボクシングで1日を設計する |
| 実績を計上する          | 実際の時間を記録する            |
| 決算レポートを読む      | AIインサイト・統計で振り返る    |
| 損益 = 予算と実績の差分 | 計画と実態のギャップが見える    |

### 使い方の指針

- **メインメッセージにはしない**（万人に通じない）
- Solution〜Featuresで「なるほど、そういう使い方か」と膝を打たせるメタファーとして投入
- 内部の統計表現（Stats画面等）にも応用可能
- 「わかってる人」が深層で共鳴するレイヤー

---

## 4. 訴求する本能

8つの本能のうち、Dayoptが刺す3つ。いずれも「自分↔自分」の関係で完結し、他者が登場しない。

| 本能       | 意味                         | Dayoptとの対応                                           |
| ---------- | ---------------------------- | -------------------------------------------------------- |
| **進める** | ゴールを設定してクリアしたい | 時間配分の可視化で「今日どれだけ進んだか」が数字で見える |
| **決する** | 自分で決めて実行したい       | タイムボクシング＝「自分で1日を設計する」行為            |
| **高める** | 自分を良くしていきたい       | パターン分析で昨日の自分を超えていく（内向きの成長）     |

参照: [instinct-mapping.md](./instinct-mapping.md)

---

## 5. Before → After

|            | 状態                                                                                          |
| ---------- | --------------------------------------------------------------------------------------------- |
| **Before** | 1日が終わって、何にどれだけ時間を使ったか説明できない。明日を今日より良くする手がかりがない。 |
| **After**  | 自分の時間の使い方が「見える」。だから明日を自分で設計できる。                                |

この変化がDayopt固有の価値。カレンダーは未来だけ、Togglは過去だけ、TODOは完了/未完了だけ。Dayoptだけが「意図と実態を1つの場所で重ねて見る」ことができる。

## 6. メッセージ二層構造

| 層       | 内容                                                               | 対象                       |
| -------- | ------------------------------------------------------------------ | -------------------------- |
| **表層** | 上位ジョブを平易な言葉で。「時間のコントロール」「自分で設計する」 | 誰にでも響く               |
| **深層** | 中位〜下位ジョブのディテール。ツール断片化、P/Lメタファー          | 「わかってる人」がうなずく |

## 7. ブランドパーソナリティ

### キーワード

- **静かに自信がある** — 大げさに煽らない。「自分の時間を自分で決める人のための道具」という落ち着いたスタンス
- **知的だけど冷たくない** — データや数字を扱うけど、目的は自己理解。分析ツールの無機質さではなく、「自分をよく知る」温かみ
- **余白がある** — 詰め込まず、必要なことだけ言う。ユーザーが自分で考える余地を残す

### 姿勢

困ってる人に手を差し伸べるのではなく、**「わかってる人に、ちゃんとした道具を渡す」**。
