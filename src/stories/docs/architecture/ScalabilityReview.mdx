## 1. N+1クエリ — DB設計

### 1-1. ~~proProcedure の毎リクエストプロフィール取得~~ (解決済み)

`src/platform/trpc/procedures.ts` — **JWTカスタムクレーム化で解決**

custom_access_token hook により `subscription_status` をJWTに埋め込み。
トークンリフレッシュ時（1時間ごと）にのみDBを参照し、以降はJWTクレームから読み取る。

- **削減効果**: 月72万クエリ → 0（hook適用済みトークン）
- **マイグレーション**: `20260319110000_custom_access_token_hook.sql`
- **フォールバック**: hook未適用の既存セッションはDBクエリにフォールバック

### 1-2. autoShrinkNeighbors のループ内UPDATE

`src/features/entry/server/entry-service.ts` L429-441

adjustments配列をforループで個別UPDATE。最大4-6クエリ/操作。

| 指標   | 値                             |
| ------ | ------------------------------ |
| 日次   | 12,000 UPDATE                  |
| 月次   | 360,000                        |
| 改善案 | PostgreSQL RPC で1クエリに統合 |

### 1-3. タグフィルター時の2段クエリ

1. `entry_tags` → `entry_id[]` 取得

## 3. Vercel Function Cold Start

### 構成

| 項目        | 値                            |
| ----------- | ----------------------------- |
| Runtime     | Node.js                       |
| Region      | `hnd1` (東京のみ)             |
| maxDuration | デフォルト (Chat APIのみ60秒) |

### Cold Start 試算

```
起動 ~300ms + モジュール初期化 ~200-500ms = 合計 500-800ms
```

| 時間帯       | 影響                                               |
| ------------ | -------------------------------------------------- |
| ピーク時     | warm維持、問題なし                                 |
| 深夜-早朝    | DAU 300ではトラフィック途切れ → 毎回cold start     |
| 海外ユーザー | 東京のみ → ネットワーク遅延 150-250ms + cold start |

### バンドルサイズ主要因

| ライブラリ            | 推定   | 全ルートで必要か    |
| --------------------- | ------ | ------------------- |
| @sentry/nextjs        | ~200KB | ✅                  |
| @supabase/supabase-js | ~150KB | ✅                  |
| stripe                | ~150KB | Webhook/Billingのみ |
| @ai-sdk/\* + ai       | ~300KB | Chat APIのみ        |

### 改善案

1. Stripe/AI SDKのdynamic import（Webhook/Chat以外のルートでバンドル除外）
2. multi-region: 海外比率20%超で `iad1` 追加
3. Cron ping: Vercel cron jobでヘルスチェック → warm維持

## 結論

**Pro 1,000人 / DAU 300 では現アーキテクチャで十分動作する。**

最大リスクは「コスト」ではなく「レイテンシ劣化」:

- ~~proProcedureの無駄なクエリ~~ → JWT化で解決
- cold startが深夜帯のグローバルユーザーに影響

月額 $170 は健全。**P1の項目を順次潰せば、3,000人規模まで大きな改修なしで耐えられる。**
