# Icon Conventions

Dayopt のアイコン運用ルール。lucide-react を単一セットとして扱い、概念 → アイコンの対応を一意に決める。視覚シグナルが濁らないよう、同一概念に複数アイコンを混在させない。

> このドキュメントは「どのアイコンをいつ使うか」の意味論ルール。サイズ / 色 / spacing の token ルールは `.claude/rules/design-system.md` を参照。視覚参照は `Foundations / Icons / ByConvention` Story を併用。
>
> 本ファイルが唯一の source of truth。編集は `src/lib/styles/tokens/IconConventions.mdx` のみ。

---

## 基本方針

- **アイコンセット**: [lucide-react](https://lucide.dev/) で統一
- **stroke-width**: `1.75`（ダーク背景前提で視認性を確保。lucide デフォルトの 2 よりやや細く、1.5 より太く）
- **サイズ**: `.claude/rules/design-system.md` の Icon Size 規約に従う
  - `size-3.5` (14px): 補助（矢印、`Eye`、`ExternalLink` 等、`text-sm` の横）
  - `size-4` (16px): 標準（ボタン内、`text-base` の横）— **インラインのデフォルト**
  - `size-5` (20px): ボタン / ナビ / 強調
  - `size-6` (24px): 見出し / ヘッダー横
- **Mixing forbidden**: 他のアイコンセット（Heroicons / Phosphor / Feather / Tabler）との併用不可。絵文字をアイコン位置に置くのも不可（テキスト内の装飾絵文字は対象外）
  - 例外: OG 画像（Satori 制約）、メールテンプレート（CSS 変数不可環境）— ただしこれらも lucide の SVG を参照する形で揃えるのが望ましい

## 意味論ルール（概念 → アイコン）

### Pro / 課金

| アイコン       | 用途                                                                        |
| -------------- | --------------------------------------------------------------------------- |
| `Crown`        | Pro tier / 課金プラン階層の表現（tier の hierarchy を示す唯一の記号）       |
| ~~`Sparkles`~~ | **使わない** — AI 専用に予約。Pro upsell に流用すると AI とのシグナルが濁る |
| ~~`Zap`~~      | **使わない** — 「速度 / パワー」の汎用記号で意味が曖昧、封印                |

### バッジ・達成記号

| アイコン    | 用途                                                |
| ----------- | --------------------------------------------------- |
| `Medal`     | 単発の達成 / 継続記念（one-year loyalty など）      |
| `Award`     | 認定系                                              |
| `Trophy`    | トーナメント / ランキング系（weekly-champion など） |
| `Gem`       | 希少性を示す長期達成                                |
| ~~`Crown`~~ | Pro tier 専用で使う（バッジには使わない）           |

バッジは「Pro tier 以外の達成」を表すため、`Crown` とは明確に分離する。達成アイコンに `Crown` を使うと、Pro tier への upgrade 誘導との視覚衝突が起こる。

### metric / badge セット内の重複禁止

同一 metric セット（`metricDefinitions.ts`）/ 同一 badge セット（`badge-definitions.ts`）内で、**異なる指標に同じアイコンを割り当てない**。追加時は既存使用を必ず `grep` で確認する:

```bash
grep -n "icon:.*IconName\|icon: 'IconName'" src/features/review/
```

重複すると、ユーザーは同じアイコンで別指標を区別できなくなる（例: `Gauge` が deepUtilization と avgFulfillment の両方に付くと判別不能）。1 アイコン = 1 指標の対応を保つ。

### AI / Insight

| アイコン    | 用途                                                                                                       |
| ----------- | ---------------------------------------------------------------------------------------------------------- |
| `Sparkles`  | AI 機能全般 + Watching AI のモードアイコン（BottomTab / PageNav / AI モードメインの empty state）          |
| `Lightbulb` | ヒント / tips（AI 由来でない一般的な示唆。UI ツアー、空状態のヒント等。AI Insight 系のアイコンとしても可） |

**判断基準**: AI が生成したもの + Watching AI モード全般 = `Sparkles`、ユーザーや静的ロジックが出すヒント = `Lightbulb`。

**履歴**: 2026-04-23 — `Eye` を本セクションから予約解除。Phase 2-C Step C-4 の BottomTab 4 タブ並びで `Eye` が生き物的・有機的に浮き、他 3 タブ（Calendar / Stats / Account、抽象的・機能的）との調和を崩す視覚検証結果による。「観察」の意味は `Sparkles` + ラベル `Watching AI` の組み合わせで担保する。`Eye` はパスワード表示切替・タグ visibility 切替等の汎用 visibility toggle 用途では引き続き使用。

### 警告 / エラー

| アイコン        | 用途                                                       |
| --------------- | ---------------------------------------------------------- |
| `AlertCircle`   | **error** — 不可逆・システム異常・同期失敗・データ取得失敗 |
| `AlertTriangle` | **warning** — 注意喚起・修正可能な問題・時間重複           |
| `Info`          | 情報提示のみ（警告ではない。ツールチップ・補足説明）       |

**判断基準**: ユーザーが「直せる」= AlertTriangle、ユーザーが直せない / システムが壊れた = AlertCircle。`design-system.md` の `ErrorState` 規約（AlertCircle）と整合する。

### ナビゲーション / ユーザー

| アイコン     | 用途                                         |
| ------------ | -------------------------------------------- |
| `UserCircle` | ナビゲーション / アバター代替 / profile 表示 |
| `User`       | 抽象的な「ユーザー」概念 / 設定項目のラベル  |

**判断基準**: 画面内で「この人」を指す（アバター、プロフィールタブ）= UserCircle、「ユーザーというカテゴリ」を指す（設定項目、dropdown の項目ラベル）= User。

### カレンダー / 日付

| アイコン       | 用途                                                                       |
| -------------- | -------------------------------------------------------------------------- |
| `Calendar`     | 日付入力フィールド / 単日参照（DatePicker, DateRow）                       |
| `CalendarDays` | ナビゲーション / 機能名 / 複数日の集計（BottomTabBar, PageNav, AppHeader） |

**判断基準**: 「1 つの日」を指す = Calendar、「カレンダー機能そのもの / 複数日」= CalendarDays。

### アクション

| アイコン | 用途                | 備考                                                                          |
| -------- | ------------------- | ----------------------------------------------------------------------------- |
| `Plus`   | 追加                | `PlusCircle` / `PlusSquare` は使わない、一律 `Plus`                           |
| `X`      | 閉じる / キャンセル | —                                                                             |
| `Trash2` | 削除                | `Trash` は使わない、`Trash2` に統一                                           |
| `Check`  | チェック / 完了     | `CheckIcon` / `CheckCircle` は使わない、一律 `Check`（shadcn 除く、下記参照） |

### アップロード / 画像

| アイコン     | 用途                                                            |
| ------------ | --------------------------------------------------------------- |
| `Upload`     | ファイル / データのアップロード                                 |
| `ImagePlus`  | Web 文脈の画像追加（プロフィール画像、アバター変更）            |
| ~~`Camera`~~ | **使わない** — Web 文脈では撮影ではなくアップロードなので誤誘導 |

### フォルダ / グループ操作

| アイコン       | 用途                                             |
| -------------- | ------------------------------------------------ |
| `FolderMinus`  | グループから外す（タグをグループから取り出す等） |
| ~~`FolderUp`~~ | **使わない** — 「アップロード」と誤読される      |

### 404 / 見失い

| アイコン           | 用途                                                                       |
| ------------------ | -------------------------------------------------------------------------- |
| `Compass`          | 「道を見失った」文脈（404 ページ）。copywriting の「地図」メタファーと整合 |
| `SearchX`          | 検索結果なしでの「見失い」表現                                             |
| ~~`FileQuestion`~~ | **使わない** — 「ファイルに疑問」の意で 404 文脈と合わない                 |

### ヘルプ / 疑問

| アイコン                    | 用途                                                          |
| --------------------------- | ------------------------------------------------------------- |
| `HelpCircle`                | ヘルプ / 疑問（FAQ リンク、ツールチップのヘルプ起動）         |
| ~~`MessageCircleQuestion`~~ | **使わない** — チャット吹き出しは AI チャット機能の予約に回す |

## カテゴリアイコン例外

複数カテゴリを並べる UI（例: チャート凡例、設定タブのアイコン）では、**individual な specific アイコン**優先で選ぶ。セット全体の視覚重量統一より、個別の識別性を優先する（Dumbbell / Baby / Leaf / Briefcase など）。

ただし以下の縛りは適用する:

- **同一アイコンの無印 / `2` 変種の混在禁止** — 例: `Building` と `Building2` を同一画面 / 同一セットで併用しない。どちらか 1 つに寄せる
- 他の意味論ルール（Pro = Crown、AI = Sparkles 等）と**競合するアイコンは選ばない**

## 例外的 suffix ルール

shadcn/ui 生成ファイル（`src/lib/components/ui/*.tsx`）内の `CheckIcon` / `XIcon` / `ChevronDownIcon` / `ChevronRightIcon` / `Loader2Icon` 等は、**コード生成物として suffix 付きのまま維持可**。手動で書き換えると CLI 再生成時に diff が出る。

app コード（`src/app/` / `src/features/` 配下）では suffix なし（`Check` / `X` / `ChevronDown` / `Loader2`）に統一する。

| 場所                                   | 記法                  |
| -------------------------------------- | --------------------- |
| `src/lib/components/ui/*.tsx` (shadcn) | `*Icon` suffix 維持可 |
| `src/app/`、`src/features/`、その他    | suffix なしに統一     |

## 新規アイコン追加時のチェックリスト

- [ ] lucide-react に存在するか（別セットに手を出さない）
- [ ] 既に同概念で使われているアイコンがないか `grep -r "from 'lucide-react'" src` で確認
- [ ] 意味論ルールのどこに属するか判断し、新概念ならこのドキュメント（`src/lib/styles/tokens/IconConventions.mdx`）に追記
- [ ] Storybook の `Foundations / Icons / ByConvention` Story に追加
- [ ] `.claude/rules/design-system.md` の Icon Size 規約に準拠するサイズで使っているか
