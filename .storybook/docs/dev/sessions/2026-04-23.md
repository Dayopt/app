learned:

- Inspector の ScheduleCard は popover / Drawer でも流用可能な構造になっており、独自 UI を書く前に Inspector 側を確認すべきだった（今日の rewrite の主因）
- Duration histogram は「価値 < 実装複雑度」で撤退判断。候補値提示は将来必要になった時に軽量 heuristic で再実装する方が安い
- 前日 WIP を翌日採用しない判断をする時、RPC / migration / client / test / Storybook を一括で追うと dead code が残らない（部分削除だと必ず artifact が残る）
- PageNav v2 の配置変更（sidebar header 直下）で視線移動が short path になり、transition 撤去と合わせて体感速度が上がる（transition は距離が短い時にむしろノイズになる）
- `forceSingleRow` のような表示密度オプションは props に明示的に持たせた方が、呼び出し側で layout 文脈を表現できる（内部で高さを推測しない）

tried_and_failed:

- 前日 WIP の duration distribution RPC + histogram UI → 撤退。pure 関数 `computeDurationDistribution` は境界テストのみ残し、RPC / client / migration は DROP
- 独自 popover UI（初日実装）→ Inspector ScheduleCard 流用に段階的 rewrite（ヘッダー色統一 → 入力エリア差し替え → Drawer 構造統一 → dead code 掃除）
