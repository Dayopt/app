- 右クリックメニューを Inspector の TagRow メニューと同じ 4 項目に統一（振り返り / 計画外にする / 計画に戻す / 削除）
- 「計画外にする」の表示条件は `origin === 'planned'` のみで判定（end_time / actual_end_time の時刻ゲートは外す）
- ドラッグ列計算の fallback は「左外なら最初の列、右外なら最後の列」に clamp（無条件で最後の列に倒す挙動を修正）

conventions:

- 同じ操作セットが複数 shell（floating menu / DropdownMenu）で出るとき、shell の共通化ではなく items 配列の共通関数化を選ぶ。consumer が `getXxxMenuItems(args, handlers)` を呼んで自前 shell でレンダー
- menu items の共通関数は `EntryMenuItem[]` のような型を返し、`labelKey` / `icon` / `onSelect` / `dangerous` を field として持つ。consumer は `t(item.labelKey)` で翻訳を解決
- feature 間の境界をまたぐ場合、共通関数は下位 feature（Layer 1 = entry）の `lib/` に置き、barrel から export して上位 feature（Layer 2 = calendar）から import する

breaking:

- TagRow の props から `onViewStats` / `onDelete` / `isUnplanned` / `onMarkUnplanned` / `onRestorePlanned` を撤去、`menuItems: EntryMenuItem[]` に置換
- useEntryContextActions の return 型に `handleViewStats` / `handleMarkUnplanned` / `handleRestorePlanned` が追加（既存 caller への影響なし、追加のみ）
- 右クリックメニューの削除ラベル: `calendar.contextMenu.delete`（"エントリーを削除"）→ `common.actions.delete`（"削除"）に変更（Inspector と統一）

learned:

- Claude Code は MCP client として動作する。`claude mcp add --transport http <name> <url>` で remote MCP を追加できる。OAuth flow は `/mcp` slash command 経由で起動
- 現状 `mcp.dayopt.app` の static client allowlist には `claude-ai` / `chatgpt` / `cursor` のみで、Claude Code は登録されていない。DCR (Phase 2) を実装するまで Claude Code からは繋がらない（接続自体が無理）
- WeekView のドラッグで列インデックスを計算する `useInteraction.ts` の fallback は左右どちらに外れても「最後の列」を返していた。Sidebar 方向にドラッグすると Friday にワープするのはこの fallback が原因

tried_and_failed:

- EntryContextMenu と TagRow を「shell ごと共通化」する案は不採用。floating menu と Radix DropdownMenu で位置計算ロジックが別物なので、items 配列だけ共通化する方が低コスト
- 右クリックメニューを「最初は items 配列を内部で手書き、shared 関数化は後回し」にしたが、ユーザー指摘で drift リスクが現実的と判明し、共通化に方針転換。最初から共通化すべきだった
