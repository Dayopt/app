- Phase 2-B の client router を完全撤去し sidebar page nav / bottom tab bar を next/link ベースに統一
- calendar / stats を `(modes)` route group 配下に移動し Phase 2-C Step C-1 を完了
- Sidebar 中身を `SidebarContent` dispatcher + `CalendarSidebar` / `StatsSidebar` / `AiSidebar` のモード別 component に分離（Phase 2-C Step C-2、Option Y pathname dispatch 採用）
- 未知 pathname の fallback は CalendarSidebar（Option α）、AI モードは Step C-2 時点で stub + pathname 判定だけ先行配置
- Inspector は calendar 外への遷移（stats / settings）時に閉じる（以前は閉じず残留していた）

- Sidebar のセクション折りたたみ機能を削除し単純な見出しに戻す（利用頻度低く UI 複雑化）
- クリック可能要素の hover 時 pointer カーソルを復元（Tailwind v4 デフォルト変更の影響回帰）

conventions:

- Client-side navigation は `next/link` / `router.push` を直接使い、独自 client router store を介さない（Phase 2-B 以降の原則）
- Composition Layer は `_shell/` 配下に置く。Sidebar 外殻（`lib/components/shell/sidebar/`）は feature 非依存のまま維持し、feature 依存の中身は `_shell/` 側
- モード別 UI の分岐は単一 component 内 props 分岐ではなく、pathname dispatcher + モード別 component への分割で実装する（拡張時の if 地獄回避）
- Document の single source of truth は Storybook MDX。`docs/features/` / `docs/icons/` 配下の重複 md は廃止
- pathname dispatch の util は `navigation-paths.ts` に集約し、locale prefix 非依存の `includes()` ベースで判定、unit test を必須化
- Inspector / modal は route 遷移で明示的に閉じる side effect を持たせる（route 側の責務として扱う）

breaking:

- `useClientRouterStore` / client page router 関連を完全削除
- `resetToServer` noop 呼び出しを撤去
- Calendar / stats の URL は `(modes)` route group 経由に変わる（URL は不変だがファイル配置が `_shell/(modes)/calendar/*` に移動）
- `SidebarContent` が直接 calendar + stats を import する構造を廃止、dispatcher + モード別 Sidebar に分離
- Sidebar セクション折りたたみ UI 撤去（折りたたみ state は不要になった）
- `docs/features/chronotype.md` / `docs/icons/icon-conventions.md` / `welcome.mdx` を削除（Storybook MDX に移設）

learned:

- Phase 2-B→C の routing 移行は「client router 撤去 → next/link 化 → route group 導入 → Sidebar 分離」の順で進めると blast radius が各 step に閉じる
- pathname dispatch は `switch` 文が 3 モード規模では object map より読みやすく、default で fallback を書きやすい
- route group `(modes)` は URL には現れないため、`pathname.includes('/calendar/')` 等の単純判定で十分（locale prefix も非依存）
- React DevTools Profiler で Sidebar 外殻の再マウント 0 回を確認することが Option Y（pathname dispatch）採否の決め手（外殻再マウントが起きれば Option X / Z を検討）
- Tailwind v4 で `cursor: pointer` のデフォルト挙動が変わったため、既存 button / clickable area に明示的な `cursor-pointer` 指定が必要になった
- Storybook MDX を single source of truth にすると、doc の二重管理（md + MDX）から解放される一方、`docs/` 配下を機械的に検索する用途では Storybook の組み込み検索に寄せる必要がある

tried_and_failed:

- Sidebar モード別分離の初期案で各 mode layout が `<Sidebar>` ごと再描画する Option X を検討 → Sidebar 外殻再マウントで state が失われるため却下、dispatch 型の Option Y に決定
- 当初 Step C-1 で相対 import path の修正漏れが残り、route group 移動後に型エラーが発生 → `e66c103fa` で補正コミット（相対 import は route group 跨ぎで path が変わることを忘れていた）
- Sidebar セクションの折りたたみ機能 → 利用頻度が低く UI を複雑化していたため撤去（折りたたみ state 管理も消失）
