# 品質ダッシュボード

プロジェクトの品質メトリクスを**構造化JSON**で統一し、定点観測するための仕組み。

---

## 概要

各品質ツールの出力を1つのJSONスナップショットに集約し、Storybookで可視化する。
週次で差分を追うことで、品質の傾向を把握できる。

### 全体の流れ

```
npm run quality:collect
    ↓
quality-reports/latest.json    ← 最新スナップショット
quality-reports/previous.json  ← 前回分（差分比較用）
quality-reports/YYYY-MM-DD.json ← 日付別アーカイブ
    ↓
Storybook「Quality Dashboard」で可視化
```

---

## メトリクス一覧

| メトリクス           | 計測内容                          | ソース                          |
| -------------------- | --------------------------------- | ------------------------------- |
| **型安全性**         | TypeScript型エラー数              | `tsc --noEmit`                  |
| **テストカバレッジ** | statements / functions / branches | Vitest + Istanbul               |
| **RLSカバレッジ**    | RLS有効テーブル数 / ポリシー数    | マイグレーションSQL解析         |
| **Storyカバレッジ**  | Story付きUIコンポーネント率       | `src/components/ui/` スキャン   |
| **Feature境界違反**  | cross-feature import数            | `.feature-boundary-budget.json` |
| **循環依存**         | 循環参照サイクル数                | madge                           |
| **Dead Code**        | 未使用export / ファイル数         | knip                            |
| **アクセシビリティ** | axe違反数                         | Storybook Vitest                |

## コマンド

### フル収集

```bash
npm run quality:collect
```

全メトリクスを収集。テスト実行やStorybook Vitestを含むため **10〜15分** かかる。

### 高速収集

```bash
npm run quality:collect:fast
```

a11yとテストカバレッジをスキップ。**1〜2分**で完了。ローカルでの確認用。

### 部分スキップ

```bash
npm run quality:collect -- --skip=a11y,deadCode
```

`--skip` に任意のメトリクスキーをカンマ区切りで指定できる。

使用可能なキー: `typeSafety`, `testCoverage`, `rlsCoverage`, `storyCoverage`, `featureBoundaries`, `circularDeps`, `deadCode`, `a11y`

### Dead Code単体確認

```bash
npm run quality:deadcode
```

knipのJSON出力を直接確認。

## JSON スキーマ

各スナップショットは以下の構造:

```json
{
  "version": 1,
  "timestamp": "2026-03-19T09:00:00.000Z",
  "gitSha": "957756c",
  "metrics": {
    "typeSafety": { "errors": 0, "status": "pass" },
    "testCoverage": {
      "statements": { "covered": 1200, "total": 1800, "pct": 66.67 },
      "functions": { "covered": 350, "total": 500, "pct": 70.0 },
      "branches": { "covered": 280, "total": 450, "pct": 62.22 }
    },
    "rlsCoverage": {
      "tablesWithRls": 17,
      "totalTables": 17,
      "pct": 100,
      "policies": 73
    },
    "storyCoverage": { "covered": 34, "total": 34, "pct": 100 },
    "featureBoundaries": { "violations": 0 },
    "circularDeps": { "count": 2 },
    "deadCode": { "unusedExports": 15, "unusedFiles": 3 },
    "a11y": { "violations": 0, "status": "pass" }
  }
}
```

型定義: `scripts/quality-metrics-schema.ts`

## ダッシュボードの見方

### 色

- **緑**: 良好（カバレッジ80%以上、エラー0）
- **黄**: 注意（カバレッジ60〜80%）
- **赤**: 要対応（カバレッジ60%未満、エラーあり）

### 差分バッジ

各メトリクスの横に前回との差分を表示:

- `+3` 緑: 改善方向に増加
- `-2` 赤: 悪化方向に変化
- `±0` グレー: 変化なし

「型エラー」「違反数」など**少ないほど良い指標**は色が反転する（増加=赤、減少=緑）。

## CI 自動収集

`.github/workflows/quality-dashboard.yml` で毎週月曜 09:00 UTC に自動実行。

1. `npm run quality:collect -- --skip=a11y` を実行
2. `quality-reports/` の変更をコミット＆プッシュ
3. 次にStorybookを開いたときに最新データが反映される

手動実行: GitHub Actions の workflow_dispatch からトリガー可能。

## ファイル構成

```
scripts/
  quality-metrics-schema.ts    # 型定義
  collect-quality-metrics.ts   # 収集スクリプト

quality-reports/
  latest.json                  # 最新（Storybook読み込み用）
  previous.json                # 前回（差分表示用）
  YYYY-MM-DD.json              # 日付別アーカイブ

src/stories/docs/quality/
  QualityDashboard.stories.tsx  # Storybook Story
  QualityDashboard.mdx          # このドキュメント
  quality-dashboard/
    QualityDashboard.tsx        # ダッシュボード本体
    MetricCard.tsx              # メトリクスカード
    DeltaBadge.tsx              # 差分バッジ
    CoverageBar.tsx             # カバレッジバー
    StatusIndicator.tsx         # ステータスドット
    sample-data.ts              # サンプルデータ
    types.ts                    # 型定義
    index.ts                    # re-exports
```

## 新しいメトリクスの追加方法

1. `scripts/quality-metrics-schema.ts` の `QualitySnapshot['metrics']` に新しいキーを追加
2. `src/stories/docs/quality/quality-dashboard/types.ts` にも同じ型を追加
3. `scripts/collect-quality-metrics.ts` に `collectXxx()` 関数を追加し、`collectors` 配列に登録
4. `QualityDashboard.tsx` に新しい `MetricCard` を追加
5. `sample-data.ts` にサンプル値を追加
