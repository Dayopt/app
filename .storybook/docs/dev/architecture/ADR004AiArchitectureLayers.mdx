# ADR-004: 3層AIアーキテクチャ

> accepted（2026-03-02・遡及記録）

---

## コンテキスト

Claude Codeへの指示が散在し、以下の問題が発生していた：

- CLAUDE.md、個別ルールファイル、口頭指示が混在し、AI行動の再現性が低い
- 設計原則からの逸脱が繰り返され、都度修正が必要だった
- タスクごとに必要な知識の粒度が異なるが、全情報を一括でコンテキストに載せるのは非効率

知識を階層化し、状況に応じて適切なレベルの情報をAIに提供する仕組みが必要だった。

---

## 決定

AI向けの知識を3層構造で階層化する。Layer 1（rules）は常時ロードされる行動規範、Layer 2（skills）はタスク発動時に展開されるドメイン知識、Layer 3（MCP）は外部ツールアクセス。加えて、拡張思考バジェットとサブエージェントのモデル選択ガイドラインを定義する。

---

## 詳細

### Layer 1: Rules（行動規範）

`.claude/rules/` に配置。パスパターンに基づき関連ファイル編集時に自動ロードされる。

- `ai-behavior.md` — 拡張思考バジェット、曖昧指示への対応方針
- `feature-boundaries.md` — DAG定義・依存ルール
- `temporal-constraints.md` — 時間制約マトリクス
- `design-system.md` — デザイントークン使用規則

### Layer 2: Skills（タスク特化知識）

`.claude/skills/` に配置。スラッシュコマンドまたは自動検出で発動。

- `storybook/` — Story作成パターン
- `docs-writing/` — ドキュメント執筆ガイド
- `trpc-router-creating/` — tRPCルーター作成手順
- `optimistic-update/` — 楽観的更新パターン

### Layer 3: MCP（外部ツール）

`.mcp.json` で定義。ADR-003参照。

### 拡張思考バジェット

| キーワード     | 思考予算       | 使用ケース                          |
| -------------- | -------------- | ----------------------------------- |
| `think`        | 低（5-10秒）   | 既存パターン確認、簡単なバグ特定    |
| `think hard`   | 中（30-60秒）  | 複雑なロジック設計、選択肢比較      |
| `think harder` | 高（2-3分）    | アーキテクチャ変更、複数機能の統合  |
| `ultrathink`   | 最大（5-10分） | CLAUDE.md変更、プロジェクト全体方針 |

### サブエージェントモデル選択

| モデル | タスク                                   |
| ------ | ---------------------------------------- |
| Haiku  | ファイル検索、Grep、ドキュメント調査     |
| Sonnet | 通常のコード実装、バグ修正（デフォルト） |
| Opus   | 5+ファイル変更、アーキテクチャ設計       |

---

## 結果

### メリット

- AI行動の再現性が向上し、同じ種類のタスクで一貫した品質を維持
- コンテキストウィンドウの効率的な利用（必要な知識のみロード）
- 新しいドメイン知識の追加がskill追加で体系的に行える
- 拡張思考バジェットにより、タスクの複雑さに応じた思考時間の配分が可能

### トレードオフ

- rules/skillsファイルのメンテナンスコスト（コードベースの変化に追従が必要）
- 3層の境界が曖昧なケースがある（rulesに書くべきかskillsに書くべきか）
- Claude Code固有の仕組みに依存しており、他のAIツールへの移植性は低い
