# 創業者のエピソード

コンテンツ作成の素材として使う、創業者の実体験・エピソード集。

---

## 1. 挫折の経験

### 試したツール

Motion, Todoist, Things など大手のタスク管理ツールは有料・無料問わず全部試した。

### 続かなかった理由

**タスクリストの限界**

- タスクリストに書いても、カレンダーにないと結局やらない
- 「タスクリストにする意味がわからない」という感覚
- 文字にするのがめんどくさい

**振り返りが活かせない**

- ToDoを見返しても「で、何？」となる
- 統計で何かわかるわけでもなかった
- 記録しているのに次に活かせない

**記録価値とのモヤモヤ**

- 記録として残ることには価値を感じる
- でも実行には繋がらない
- 捨てがたいけど使えない、その間でモヤモヤ

### 離脱のパターン

「もう無理」と爆発するのではなく、**「これ使う意味ないな」と静かに離脱**する。

### 根本の気づき

- 「紙でやる方が楽だな」
- 「詳細に管理することに時間を使うのが無駄なんじゃないか」

→ **管理コスト > 管理のメリット** になっていた。ツールが「整える」ためのものなのに、ツール自体が負担になる矛盾。

### 欲しかったもの

- 自分では気づけない視点からのフィードバック
- 主観から抜け出すためのAIとの壁打ち
- 認識を変えてくれるような問いかけ

## 2. Dayoptのアイデアが生まれた経緯

### 時間記録への確信

- 生産性を上げる本や、時間記録の科学的根拠を読んできた
- 実際に効果があると実感している
- 時間記録自体の価値は確信がある

### 「選択型」という発想

**ToDoリストは終わらない**

- タスクは無限に増える
- 並べるだけでは終わらない

**選んでブロックするとスッキリする**

- 「今日はこれをやる」と決める安心感
- 無限のToDoから解放される感じ
- 「自分で選んだ」という納得感

→ **安心感・解放感・納得感**。これがDayoptの核心。

### 「これだ」と思った瞬間

タイムボクシング用のフォーム（紙）を見たとき。

- **予定と記録を同時に書く**というページ構成
- 「あ、これ欲しかった」と思った
- これをオフラインじゃなくてオンラインにしたい

→ 既存の紙フォーマットにヒントがあり、それをデジタル化したかった。

## 3. 開発中の迷い・判断

### 基本方針：スーパーアプリにしない

ClickUpやNotionのように「何でもできる」方向には行かなかった。

**理由:**

- 機能が増えすぎると、使うための負荷が高くなる
- 頭の中で処理しきれない
- 「アナログの良さ」が失われる
- 詳細に管理することに時間を使うのは本末転倒

→ **削る削る削る**という気持ちで作った。

### 削った機能：タイマー

タスクの開始〜終了を自動計測するタイマー機能は入れなかった。

**理由:**

- 自動で記録されると覚えていない
- 数字は残るけど「よくした」という感覚が作られない
- **自分で手を動かして記録する**ことに意味がある
- 「自分で選んだ」感覚が高まる

| アプローチ       | 得られるもの             | 失われるもの           |
| ---------------- | ------------------------ | ---------------------- |
| タイマー自動計測 | 正確なデータ             | 記憶、達成感           |
| 手動で記録       | 「選んだ」「やった」感覚 | 正確性（でも別にいい） |

→ Dayoptは**データより体験**を重視。Togglとの明確な差別化。

### UIの変遷：カラム数

**最初の構想:**

- Slack風の3カラム（左にアイコンサイドバー）
- いろいろな機能を切り替えられる設計

**最終形:**

- ChatGPT風の2カラム（サイドバー + メイン）
- 機能を削った結果、3カラムにする必要がなくなった

### あえて残した工夫：ステータスバー

VSCode/Cursorのステータスバーにインスピレーションを得た。

| 位置 | 表示内容     | 理由                                             |
| ---- | ------------ | ------------------------------------------------ |
| 左下 | 今の予定     | ネットで色々触ってると「今何すべきか」忘れるから |
| 右下 | クロノタイプ | 今が集中できる時間帯か、色でパッとわかる         |

**機能:**

- 左下クリック → 予定に飛べる / 予定がなければ追加できる
- 右下 → 色が変わるのでパッと状態確認できる

→ エディターでブランチ確認するのと同じ感覚で「今の状態」が見える。小さくても**常に見えている情報**に価値がある。

## 4. 競合を見て感じたこと

### Toggl 2年使用の経験

Togglを約2年間、毎日記録し続けた。入力体験は良かったが、モヤモヤが残った。

**感じた課題:**

- データは溜まるのに「積もっていく感じ」がない
- 記録しても振り返りにつながらない
- 「これだけ記録して、で、何？」という感覚

### Googleカレンダー連携の限界

TogglはGoogleカレンダーとAPI連携できたが…

| 状態                       | 問題 |
| -------------------------- | ---- |
| データとしては繋がっている | ✓    |
| 体験として繋がっている     | ✗    |

→ **「リレーションされていない」** という感覚。予定と記録を同時に見て差分を確認したいのに、それができなかった。

### アナリティクスの不満

Togglにもアナリティクスはあった。でも…

- 「この週は何時間働いた」→ **だから何？**
- 見たいアナリティクスじゃない
- 次のアクションにつながらない

→ **データがあるだけでは意味がない。**

### Dayoptで解決したいこと

**1. タグによる統一**

- 予定と記録を同じタグで管理
- 同じ軸で比較できる
- 差分が見える

**2. AI連携（Claude）によるアクション提案**

- データを分析して「こうした方がいいよ」を教えてくれる
- 例：「休憩取った方がいい」「集中時間が減ってる」

**3. 価値観と行動のギャップを埋める**

多くの本が「大事なことを10個決めよう」と言う。でも行動に落とし込むのが難しい。

| 課題                                           | Dayoptの解決策                           |
| ---------------------------------------------- | ---------------------------------------- |
| 「好奇心が大事」と言っても行動に反映できない   | AIが「新しいことしてないですね」と指摘   |
| 価値観と行動が一致しているか自分で判断できない | 予定・記録データを元にAIがフィードバック |

→ **「行動することでしか人は自分を変えられない」** という信念。その行動変容を手助けする。

### 通知設計の考え方

**プッシュで生成、プルで消費**

| 方式                           | 評価     |
| ------------------------------ | -------- |
| ポップアップで急に割り込む     | ✗ ウザい |
| 通知ページにAIの気づきが溜まる | ◎ 良い   |
| 自分のタイミングで見に行く     | ◎ 良い   |

→ AIは裏で分析して気づきを生成するが、ユーザーの邪魔はしない。見たいときに見に行く形式。

### Togglとの差別化まとめ

| Toggl                        | Dayopt                                   |
| ---------------------------- | ---------------------------------------- |
| 記録が溜まるだけ             | 記録が振り返りにつながる                 |
| データはあるけど「で、何？」 | AIがアクションを提案                     |
| 予定と記録が別々             | タグで統一、差分が見える                 |
| 通知はない                   | AIの気づきが溜まる（自分のペースで確認） |

## 5. 名前「Dayopt」に込めた想い

### 名前の構造

**Dayopt = Day + opt**

- Day：1日、日付
- opt：選択（option）、最適化（optimize）

**略すと「DO」**

- do = やる
- Dayoptの「やる」を大事にするコンセプトと繋がる

### 最初の名前は「ボックスログ」

タイムボクシングの「ボックス」＋「ログ」。機能を直接表す名前だった。

**変えた理由:**

- 「ボックス」だとファイル系サービスに見える
- 「ログ」だと記録だけに見える
- 「時間」「日付」がわかる名前にしたかった
- 「記録」より上位の概念「選択・最適化」を表現したかった

→ 記録（ログ）で終わらず、**選んで最適化していく**ツールだと伝えたかった。

### 「自分に最適化」= 納得感

**最適化のイメージ:**

- 世間一般の「最適」ではない
- 自分にとっての「最適」
- 自分に最適だと思える = その状態に納得できている

**きっかけ:**

- クロノタイプを知ったこと
- 「自分に合った時間の使い方がある」と気づいた
- タスクの粒度も人それぞれ
- だから「自分に最適化」していく必要がある

### 万人向けではなく、ハマる人に

> 「すべての人の最適にはなれない。でも、これが合うと思った人にはハマる状態を作りたい」

- 万人受けを狙うと誰にも刺さらない
- 「自分にとってこのやり方だな」とハマる感覚を作りたい

### 名前を見た時に思ってほしいこと

> 「1日を選ぶためのツールなんじゃないか」

- Day（1日）を opt（選ぶ）
- 1日を選ぶ、1日を作っていく
- シンプルにそう思ってもらえたら理想
