## 環境変数の管理

### 自動同期

`npm run dev` を実行すると、`vercel env pull` が自動で `.env.local` を最新化する。
Vercel ダッシュボードで環境変数を変更 → 次の `npm run dev` でローカルに反映。

### Zodバリデーション

サーバーサイド環境変数は `src/env.ts` で起動時にバリデーション。
必須変数が欠けていると、具体的なエラーメッセージで即座に検知できる。

```typescript
// サーバーサイドコード
import { env } from '@/env';

const supabase = createServerClient(
  env.NEXT_PUBLIC_SUPABASE_URL,
  env.NEXT_PUBLIC_SUPABASE_ANON_KEY,
  { ... }
);
```

> **注意**: `NEXT_PUBLIC_*` はNext.jsがビルド時に文字列置換するため、
> クライアントコード（`client.ts`等）では従来通り `process.env` を直接参照する。

### `.env.example`

プロジェクトルートに `.env.example` がある。手動設定が必要な場合はこちらを参照。

## 分離仕様

### DB の分離

- Preview と Production のデータベースは**完全に独立**
- 本番データは Preview に存在しない
- テストデータは自由に作成・削除可能

### Auth の分離

- 各環境のユーザーアカウントは**共有されない**
- Preview でサインアップ → Preview のみログイン可能
- 本番アカウントで Preview にはログインできない

### Vercel 環境変数

```
Production     → 本番 Supabase
Preview        → ステージング Supabase（全 Preview ブランチ共通）
Development    → ステージング Supabase（vercel env pull で同期）
```

## オフライン開発（フォールバック）

ネットワーク接続がない場合、ローカル Supabase を使用できる。

```bash
# ローカルDBを起動（Docker必要）
supabase start

# 環境変数でローカルDBを指定
USE_LOCAL_DB=true npm run dev
```

> 通常の開発ではDocker不要。オフライン時のみ使用。

## マイグレーション

マイグレーションは各環境に**個別に適用**が必要。
詳細な手順は `docs/development/migration-checklist.md` を参照。

### Preview（自動）

`main` ブランチに `supabase/migrations/**` の変更がpushされると、
GitHub Actions（`.github/workflows/supabase-migration.yml`）が自動で Preview Supabase に適用。

### Production（手動）

```bash
supabase link --project-ref qloztwfbrbqtjijxicnd
supabase db push
```

### Preview Supabase のリセット

```bash
npm run db:reset-preview
```

### リンク状態の確認

```bash
supabase projects list
# LINKED列に●があるプロジェクトが現在リンク中
```

## GitHub Actions Secrets

CI/CD ワークフローで使用するシークレット一覧。GitHub の Settings > Secrets and variables > Actions で管理。

| シークレット名                  | 用途                          | 使用ワークフロー       |
| ------------------------------- | ----------------------------- | ---------------------- |
| `SUPABASE_ACCESS_TOKEN`         | Supabase CLI 認証             | migration, integration |
| `STAGING_DB_PASSWORD`           | Staging DB パスワード         | migration (staging)    |
| `PRODUCTION_DB_PASSWORD`        | Production DB パスワード      | migration (production) |
| `NEXT_PUBLIC_SUPABASE_URL`      | Supabase URL（ビルド時）      | ci, e2e                |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase 匿名キー（ビルド時） | ci, e2e                |
| `NEXT_PUBLIC_APP_URL`           | アプリ URL（ビルド時）        | ci, e2e                |

### GitHub Environments

| 環境名        | 用途                        | 保護ルール     |
| ------------- | --------------------------- | -------------- |
| `development` | E2E / Integration テスト    | なし           |
| `production`  | Production マイグレーション | 手動承認が必要 |

> **production environment の設定**: GitHub > Settings > Environments > production > Required reviewers を有効化し、自分を追加する。これにより `migrate-production` ジョブが自動実行されず、承認を待つ。

## デプロイフロー

```
feature branch → push → Vercel Preview URL 自動生成
                  ↓
              PR → main マージ
                  ├── Vercel: 自動 Production デプロイ
                  └── GitHub Actions: Preview Supabase にマイグレーション自動適用

バージョン記録（任意）:
  git tag v0.X.0 → GitHub Actions → GitHub Release 作成
  ※ タグはデプロイトリガーではない
```

## 実機テスト手順

1. ブランチをプッシュ

   ```bash
   git push origin feature/xxx
   ```

2. Vercel が自動で Preview デプロイ

3. Preview URL にモバイルでアクセス
   - 固定URL: `dayopt-git-{branch}-t3-nicos-projects.vercel.app`

4. Preview でサインアップしてテスト

## トラブルシューティング

| 症状                           | 対処                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------ |
| Preview にログインできない     | Preview 環境で新規サインアップが必要（本番アカウントは使えない）                     |
| マイグレーションが反映されない | 対象環境にリンクしてから `supabase db push` を実行                                   |
| Preview デプロイがエラー       | Vercel ダッシュボードでビルドログを確認                                              |
| Production が paused           | Supabase ダッシュボード → Settings → General → Resume                                |
| 環境変数エラーで起動しない     | `vercel env pull .env.local` を実行、または `.env.example` を参照                    |
| ローカルとPreviewで動作が違う  | 同じDBを使うため通常は発生しない。`.env.local` が古い場合は `npm run dev` で自動更新 |
