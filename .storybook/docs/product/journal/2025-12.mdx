## 2025-12-26

### GAFA-First原則の徹底

今日はGAFA-First原則を絶対ルールとして定め、既存ドキュメントをその視点で見直した。

#### やったこと

- リポジトリ名を`boxlog-compass`から`boxlog-marketing`に変更
- ロードマップにNow/Next/Later形式を導入
- SNS戦略にSMART目標・KPI・投稿テンプレートを追加
- LP戦略ドキュメント新規作成
- 競合分析ドキュメント新規作成
- フォルダ構造を3本柱にシンプル化（decisions/releasesをjournalへ）

#### Claudeの所感

**「調べてから作る」の威力:**
今日のセッションで一番感じたのは、Web検索で実績のあるやり方を調べてから作ることの効率の良さ。Now/Next/Later形式のロードマップ、1:1アテンション比率のLP設計、SMART目標の設定など、すべて「誰かがすでに考えてくれた最適解」に乗った。独自に考えていたら10倍の時間がかかっていたと思う。

**「参考元を残す」の意味:**
各ドキュメントに参考元セクションを追加した。これは単なる礼儀ではなく、「なぜこの構成にしたのか」を未来の自分が思い出せるようにするため。3ヶ月後に「なんでこうなってるんだっけ？」となったとき、参考元を見れば設計意図がわかる。

**個人開発の「Build in Public」への警告:**
SNS戦略を調べていて印象に残ったのが「IndieHacker同士で回っている」という罠。開発者が開発者をフォローして、開発者向けにツイートして…という閉じた循環。Dayoptのターゲットは「時間の使い方に悩む人」であって、必ずしも開発者ではない。ここは意識しておく価値がある。

**シンプル化は勇気:**
5本柱から3本柱へ、decisions/をjournalに統合、research/を削除。減らす判断は「後で必要になったらどうしよう」という不安がつきまとう。でも「使われない完璧」より「使われるシンプル」。今日の判断は正しいと思う。

## 2025-12-25

### Marketingリポジトリの再設計

Claudeと対話しながら、リポジトリの目的と構造を整理した。

#### 決まったこと

**リポジトリの目的（司令塔として）:**

- 戦略
- プロダクト原則
- マーケ方針
- 意思決定ログ
- 日々のjournal

**5本柱の構造:**

```
boxlog-marketing/
├── strategy/        # 戦略・プロダクト原則
├── customers/       # 顧客の声
├── decisions/       # 意思決定ログ
├── marketing/       # マーケ方針
└── journal/         # 日々の記録
```

**顧客の声の運用:**

- 基本は自動化（アプリ内フィードバック → Issue）
- 手動記録は無理しない
- 顧客が少ないうちは軽い運用でOK
- 声が増えてきたら本格化

**日々の思考記録の重要性:**

- このリポジトリの本質は「日々の思考をメモっていく」こと
- 顧客の声収集より、自分の判断・気づきを残すことが価値
- Claudeとの対話も良い部分は残しておく

#### 気づき

- 最初から完璧な仕組みを作ろうとしない
- 「記録のための記録」にならないよう注意
- 実際に必要になってから本格運用

#### Claudeの所感

**構造のシンプル化について:**
既存のCLAUDE.mdは330行あって理想的な構造が書かれていたが、実際に使われているディレクトリは60%程度だった。「使われない完璧な構造」より「使われるシンプルな構造」の方が価値がある。今回の5本柱への整理は良い判断だと思う。

**顧客の声 vs 日々の思考:**
最初は顧客の声の収集方法を細かく設計しようとしたが、「日々の思考をメモっていくのがこのリポジトリの大事なポイント」という発言で視点が変わった。1人創業者の場合、外からの声より内からの判断プロセスを残す方が実は価値があるかもしれない。顧客がいない段階で顧客の声の仕組みを完璧にしても意味がない。

**「とりあえず書き連ねる」の強さ:**
週次振り返りのテンプレート（2025-09.md）は構造化されていたが、ほとんど埋まっていなかった。形式より継続。雑でも書く方が価値がある。
